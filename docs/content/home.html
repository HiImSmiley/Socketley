What it is

socketley is one binary. Run as socketley daemon it keeps runtimes: long-living network services, each made with one command, each running in a worker process of its own on an io_uring event loop. Run as anything else it is the CLI that talks to that daemon over a unix socket, the way docker talks to dockerd.

A runtime has a type and a name. The type decides what it speaks; the name is how everything else reaches it: a proxy routes to --backend api, a server script asks the cache store, the DNS runtime answers for the names runtimes are given. Every runtime is created, started, stopped, edited, exported and removed the same way, and comes back by itself when the daemon restarts.
