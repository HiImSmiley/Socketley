What to settle before socketley runs something that matters.

The service and who may use it

  • The installed daemon is the systemd unit socketley; it restores every runtime at boot and logs to the journal.
  • The socketley group can create, stop and script every runtime: treat membership like sudo.
  • The unit grants CAP_NET_BIND_SERVICE, so runtimes may bind ports below 1024.

What is exposed

  • Keep local things on --bind 127.0.0.1 or --listen unix:. A cache is local unless created --public.
  • Put public HTTP behind the entrance: --domain names, ACME certificates, --auth and an idp for sign-in.
  • Cap what a client may cost: --max-connections, --rate-limit, --global-rate-limit, --idle-timeout, --read-buffer, --write-buffer.

State and backups

  • A runtime's state file can hold secrets such as a master password; see a state file is a secret.
  • Back up from a timer with socketley export --full file; socketley restore file puts it back.

Watching it

  • A metrics runtime raises alerts; the daemon sends them per daemon.alert_webhook and daemon.alert_mail.
  • The dashboard shows every runtime, its log and its figures.

Recipe: a public HTTPS site with a Lua handler

The goal: https://shop.example.com answered by a Lua script, with a real certificate, on one machine with the public address 203.0.113.7.

  1. Serve the domain's DNS from this machine. The dns runtime writes a zone whose name servers ns1 and ns2 point here, and makes the entrance: a proxy on 443 (with a redirect from 80) that gets its own certificates.

    socketley create dns ns --zone example.com --publish 203.0.113.7 -s

  2. Delegate the domain. At your registrar, set ns1.example.com and ns2.example.com as the name servers, both with the glue address 203.0.113.7. The entrance asks Let's Encrypt for the certificates by itself, and asks again until the delegation is visible.

  3. Write the handler, shop.lua:

    function on_http_request(req)
    if req.path == "/" then
        return { status = 200, headers = { ["Content-Type"] = "text/plain" }, body = "hello\n" }
    end
    return { status = 404, body = "not found\n" }
end

  4. Create the site. --domain shop becomes shop.example.com under the zone; --bind 127.0.0.1 keeps its own port off the network, since visitors come through the entrance.

    socketley create server shop -p 9100 --bind 127.0.0.1 --lua shop.lua --domain shop -s
curl https://shop.example.com/

A request now goes browser → entrance on 443 (TLS ends here) → the server shop → on_http_request. See How it works for the path, and the dns runtime for --publish behind NAT.

If your DNS stays with another provider, the entrance has no names to route, because it learns them from the dns runtime. Point an A record for shop.example.com at this machine instead, and let the server hold port 443 and its certificate itself; it proves the name on that port.

socketley create server shop -p 443 --acme shop.example.com --acme-email you@example.com --lua shop.lua -s

Only one runtime can hold 443 on an address, so for several sites the entrance is the better way.

Recipe: moving to a new machine

  1. On the old machine, archive everything: every runtime, their data (buckets, mailboxes, a cache's file, zones, keys and certificates) and the daemon's configuration.

    socketley export --full /var/backups/socketley.tar.gz

  2. On the new machine, install socketley, copy the archive over, and restore it with the daemon stopped. Each runtime comes back running where it ran.

    systemctl stop socketley
socketley restore /var/backups/socketley.tar.gz
systemctl start socketley
socketley ls

  3. Check what it names. The archive leaves out logs, output files, backup directories and what sync runtimes carry, and restore leaves paths under /etc, /usr and the like for you to take out with tar; both commands list these when they finish.

  4. If the new machine has another public address, three places still name the old one: the glue at your registrar, the dns runtime's --publish, and the zone file it wrote (its ns1, ns2 and the zone's own address, under the state directory's zones/). Edit the zone file, then give the runtime the new address:

    echo '{"publish":"198.51.100.4"}' | socketley import ns --restart
