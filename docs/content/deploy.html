What to settle before socketley runs something that matters. Each point links to the part of the manual that decides it.

The service and who may use it

  • Installed, the daemon runs as the systemd unit socketley under its own account and restores every runtime at boot. systemctl status|restart socketley; its log is in the journal.
  • Only root and the socketley group reach the control socket. Membership is the right to create, stop and script every runtime, so treat it like sudo for this service. Anyone else gets a private daemon of their own, not an error.
  • A runtime may bind a port below 1024 because the packaged unit grants CAP_NET_BIND_SERVICE.

What is exposed

  • Bind what only the machine needs with --bind 127.0.0.1 or put it on a unix socket with --listen unix:; a cache serves this machine only unless created --public.
  • Put public HTTP behind the entrance: one proxy on 80/443, names with --domain, certificates by ACME, --auth where people must sign in, an idp for who they are.
  • Limit what a client may cost: --max-connections, --rate-limit, --global-rate-limit, --idle-timeout, --read-buffer, --write-buffer.

State and backups

  • A state file can hold secrets (passwords, keys, a relay's password): see a state file is a secret.
  • socketley export --full file archives configuration and data in one file; socketley restore file puts it back. Run it from a timer.
  • Know each runtime's durability flag: a cache's --persistent, a storage's --fsync, an mqtt broker's --persistent, a metrics runtime's --durable.

Watching it

  • A metrics runtime keeps the history and raises alerts; the daemon carries them by webhook and mail (daemon.alert_webhook, daemon.alert_mail in the daemon configuration).
  • The dashboard shows every runtime, its log and its figures.
