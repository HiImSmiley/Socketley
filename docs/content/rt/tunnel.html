A tunnel makes a machine with no address of its own reachable, such as one at home behind a router. An agent there dials out to an edge the internet reaches; nothing is opened on the router.

# on the machine with the address
socketley create tunnel edge --mode edge -p 9450 --domain edge --idp auth -s
# on the machine at home, signed in as an admin of auth
socketley tunnel join https://edge.example.com --http home=127.0.0.1:8123 \
    --tcp mc:25565=127.0.0.1:25565

What it does

HTTP services

Named beside the edge, such as home.example.com.

TCP services

A port on the edge, carried unchanged to the agent.

Joining

socketley tunnel join as an idp admin, or a one-time invite used with --join.

ssh through 443

--forward carries a signed-in person to the named addresses, via tunnel connect or tunnel ssh.

Share a port

socketley tunnel share publishes a local port for a while, optionally public.

Works with

The edge machine needs what the public HTTPS recipe sets up: a dns runtime, which answers the services' names, and its entrance proxy, which terminates TLS. It also needs an idp runtime, here auth: its admins may join agents, and its users sign in for --forward.
