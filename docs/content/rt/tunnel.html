A tunnel runtime makes a machine that has no address of its own reachable: one at home behind a router, behind carrier-grade NAT, or on a network that lets only port 443 out. That machine runs an agent that dials out to an edge, a tunnel runtime on a machine the internet reaches, and holds the connection open; the edge serves the agent's services under its own names and carries each visitor through the connection the agent made. Nothing is opened on the router.

# on the machine with the address
socketley create tunnel edge --mode edge -p 9450 --domain edge --idp auth -s
# on the machine at home, signed in as an admin of auth
socketley tunnel join https://edge.example.com --http home=127.0.0.1:8123 \
    --tcp mc:25565=127.0.0.1:25565

What it does

  • HTTP services are named beside the edge (home.example.com), served by the entrance with its certificate, the dns runtime answering the name.
  • TCP services are a port on the edge; what reaches the agent is what the visitor sent.
  • Joining: socketley <edge> invite prints a one-time invitation an agent joins with (--join), or an admin of the edge's idp joins directly with socketley tunnel join.
  • Signed-in access: --forward carries a signed-in person's stream to an address, as ssh's ProxyCommand asks; socketley tunnel connect is that command.
  • Sharing a port for a while: socketley tunnel share publishes a local port through an edge, optionally public, for a set duration.
