A server listens on one port and talks to whoever connects. Without a script it relays messages between clients; with Lua it becomes an API, a chat room or a game loop.

socketley create server chat -p 9000 -s                    # every line reaches every other client
socketley create server echo -p 9001 --send-to sender -s   # answers whoever spoke
socketley create server site -p 8080 --http /srv/site --http-cache -s
socketley create server api -p 9002 --lua api.lua --cache store -s
--cache also stores every ordinary message in the cache, under keys 1, 2, 3… And --http injects a WebSocket script into every HTML page.

What it does

One port, several protocols

TCP, WebSocket, HTTP and RESP, told apart by their first bytes; --udp for datagrams.

Static files

--http serves a directory; --http-cache holds it in memory.

Lua handlers

Per message, connection, HTTP request and WebSocket upgrade; see Lua.

Relaying without code

--mode and --send-to decide who hears a message.

Upstreams

-u host:port dials other servers; the script hears them in on_upstream.

A cache beside it

With --cache name, clients send cache <command>; see cache access.

Several cores

--shards N runs N processes on one port; see sharding.

Works with

A proxy in front for names and TLS, a cache behind for state, a client to chain servers. Its counters reach metrics without setup.
