A server is one port for long-lived connections: TCP lines, WebSocket, HTTP and RESP on the same port, or UDP datagrams. Without a script it relays messages between clients; with Lua it answers them, as a chat room, a game server, a line protocol or an API.

socketley create server chat -p 9000 -s                    # every line reaches every other client
socketley create server echo -p 9001 --send-to sender -s   # answers whoever spoke
socketley create server room -p 9003 --lua room.lua -s     # the script decides who hears what
socketley create server site -p 8080 --http /srv/site --http-cache -s
socketley create server api -p 9002 --lua api.lua --cache store -s
-- room.lua: whoever sends "join" hears everything said in the room
function on_client_message(id, msg)
  if msg == "join" then self.join_group(id, "room") else self.group_send("room", msg) end
  return true   -- handled, so nothing is relayed on its own
end
--cache also stores every ordinary message in the cache, under keys 1, 2, 3… And --http injects a WebSocket script into every HTML page.

What it does

One port, four protocols

TCP lines, WebSocket, HTTP and RESP, told apart by their first bytes; --udp for datagrams, where on_client_message names the peer and self.send answers it.

Lua per message

on_client_message answers with self.send and returns true to keep the relay out; connects, disconnects, requests and upgrades have callbacks too. See Lua.

Broadcast and rooms

self.broadcast reaches everyone, self.multicast a list, self.join_group and self.group_send a room.

Relaying without code

--mode and --send-to decide who hears a message; --send-to sender is an echo server.

HTTP on the same port

on_http_request answers requests; --http serves a directory, --http-cache holds it in memory.

TLS and unix sockets

--tls --cert --key encrypt the port, --ca asks for client certificates; --listen unix:/path serves a local socket.

Upstreams and a cache

-u host:port dials other servers for on_upstream; with --cache name, clients send cache <command> (cache access).

Several cores

--shards N runs N processes on one port, and a broadcast reaches every shard's clients; see sharding.

Works with

A proxy in front for names and TLS, a cache behind for state, a client to chain servers. Its counters reach metrics without setup.
