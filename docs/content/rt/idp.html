An idp is an OpenID Connect provider with its own accounts. A user signs in once, and your applications, proxy routes, storage, db, mail and the dashboard know who they are.

socketley create idp auth -p 9400 --domain auth.example.com \
    --clients /etc/socketley/idp.clients --cookie-domain example.com -s
socketley auth user add smiley --password - --groups admins

What it does

OpenID Connect

Authorization code flow with PKCE, refresh tokens, discovery at /.well-known/openid-configuration.

Accounts

Fields without a schema; fields it does not use are kept for your applications.

Sign-in

Passwords, a second step and app passwords; users manage themselves at /account.

Applications

Listed in --clients with an id, a secret or -, and redirect addresses.

Tokens for other servers

--resources gives tokens for, say, an mcp runtime, to MCP clients like Claude Code too, once the user allows it.

SSH certificates

--ssh-ca hours signs short-lived SSH certificates for signed-in users.

Works with

Put routes behind it with a proxy's --auth idp:. A db, mail or mqtt runtime takes its users with --idp.
