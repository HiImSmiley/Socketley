A proxy forwards HTTP or plain TCP to backends, balances them and steers around failing ones. Without --backend it is the entrance, routing each request by name to the runtime that has it.

socketley create proxy gw -p 8080 --backend 127.0.0.1:9000 -s          # /gw/... goes to the backend
socketley create proxy web -p 8081 --backend @web --strategy round-robin \
    --health-check http --health-path /health -s
socketley create proxy db-tcp -p 5433 --protocol tcp --backend 10.0.0.7:5432 -s
socketley create proxy php -p 8082 --backend fastcgi://127.0.0.1:9000 --root /var/www/site -s
By default a backend has 2 seconds to start answering, or the request gets a 504. Raise --backend-timeout for slow applications.

What it does

Routing

A request for /gw/x on proxy gw reaches the backend as /x; any other path, / included, gets 404. Through the entrance, a request for a --domain name passes unchanged.

Any backend

host:port, https://, unix:, a runtime, an @group, fastcgi://.

Resilience

Health checks, a circuit breaker, retries; --sidecar turns all on.

Sign-in first

--auth bearer:, basic: or idp: before anything reaches a backend.

TLS on both legs

Its own listener, client certificates, verified https:// backends.

Lua filters

on_route picks backends; a filter chain rewrites traffic.

Modern HTTP

The entrance speaks HTTP/2 and HTTP/3; every proxy relays WebSocket.

Works with

A dns runtime makes the entrance and its certificates. --auth idp: signs people in through an idp.
