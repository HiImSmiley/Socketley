A proxy is a reverse proxy for HTTP or plain TCP. In HTTP mode it routes by name and path to backends that are addresses, unix sockets, other runtimes by name or whole groups, keeps backend connections pooled, checks their health, opens a circuit on a failing one and retries elsewhere. Without a --backend it is the entrance: the one proxy on 80/443 that serves every runtime under the names given with --domain, with certificates from ACME.

socketley create proxy gw -p 8080 --backend 127.0.0.1:9000 -s          # /gw/... goes to the backend
socketley create proxy web -p 8081 --backend @web --strategy round-robin \
    --health-check http --health-path /health -s
socketley create proxy db-tcp -p 5433 --protocol tcp --backend 10.0.0.7:5432 -s
socketley create proxy php -p 8082 --backend fastcgi://127.0.0.1:9000 --root /var/www/site -s

What it does

  • Routing: a request to /<proxy-name>/… is forwarded with the prefix stripped; reached by one of its --domain names it forwards path and Host unchanged. --strategy round-robin|random|lua picks the backend, on_route in Lua decides per request.
  • Backends: host:port, https://host (verified TLS), unix:/path, a runtime's name, @group (every running member, picked up as they come and go), fastcgi:// for PHP-FPM.
  • Resilience: health checks, a circuit breaker, retries, a --backend-timeout, and a defined answer when no backend is reached; --sidecar turns the set on at once.
  • Access: --auth bearer:file|basic:file|idp:runtime asks before anything reaches a backend; idp: signs people in through an idp runtime.
  • TLS on both legs: its own listener, client certificates with --client-ca, verified https:// backends and a client certificate for them; --redirect-https.
  • Lua filters and rewriting: on_proxy_request/on_proxy_response per chunk and a filter chain; backends' declared routes answer 405 and OPTIONS without a trip.
  • The entrance speaks HTTP/2 to a client that offers it over TLS and HTTP/3 over UDP on the same port, routing each stream by its name; every proxy relays WebSocket and other upgrades, pools its backend connections and takes --shards for several cores.
