A client is the other end: a long-living connection this daemon dials and keeps, to a socketley server or anything else that speaks TCP or UDP, optionally over TLS. It reconnects with back-off when the line drops, so a script on it can treat the peer as always there, and what arrives can be printed, written to a file or handled in Lua.

socketley create client feed -t 10.0.0.5:9000 --reconnect 0 -b -s   # print what arrives, reconnect for ever
socketley send feed "subscribe prices"
socketley create client probe -t unix:/run/app.sock --lua probe.lua -s

What it does

  • Targets: -t host:port or -t unix:/path; --udp for datagrams.
  • TLS with --tls, verifying the chain against --ca or the system store and the host name from -t, presenting --cert/--key when the server asks. There is no switch to skip verification.
  • Reconnects with --reconnect [n], backing off, 0 for no end.
  • Output: -b, -bp, -bt, -bpt print each message with the name and time; -w file writes them.
  • Direction: --mode inout|in|out.
  • Lua: on_connect, on_message, on_disconnect, timers, and self.send() with back-pressure through self.pending() and on_writable.
