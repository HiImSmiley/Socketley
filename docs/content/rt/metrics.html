A metrics runtime keeps what socketley and the machines around it measure, for years, and answers with PromQL over the Prometheus HTTP API, so Grafana reads it as it reads a Prometheus. This daemon's own series reach it without any configuration; other daemons and any Prometheus endpoint are scraped. Its rules raise the daemon's alerts, it keeps log lines answered with LogQL, and the dashboard draws its history from it.

socketley create metrics metrics -p 9090 --scrape /etc/socketley/targets -s
socketley metrics query 'rate(socketley_runtime_messages_total[5m])'
socketley metrics query_range 'up' --start -6h --step 5m

What it does

  • Collecting: the daemon's own series at each tick, --scrape targets every --every, and remote write with --receive.
  • Keeping: samples stamped on the tick, one to three bytes each, cut into two-hour blocks merged into days, with five-minute and hourly tiers built beside them (--downsample); --keep bounds the age, --max-series the cardinality, and --durable logs every sample as it arrives so a crash loses none.
  • Answering: PromQL instant and range queries, series and label lookups over the Prometheus API; a long range reads the coarsest tier that still answers it exactly.
  • Alerting: --rules in Prometheus's format raise alerts that --notify and the daemon's webhook, mail and event settings carry.
  • Logs: with --logs it keeps the daemon's log lines for --logs-keep and answers LogQL as Loki does.
  • Archive: old blocks go to an S3 bucket with --archive, such as a storage runtime's.
