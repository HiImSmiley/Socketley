A cache is an in-memory data store that speaks the Redis protocol, so redis-cli and Redis libraries work unchanged. nc works too, in plain text.

socketley create cache store -p 6379 -s
redis-cli -p 6379 SET greeting hello
redis-cli -p 6379 GET greeting

socketley create cache sessions -p 6380 --maxmemory 512M --eviction allkeys-lru \
    --persistent /var/lib/socketley/sessions.bin -s
socketley create cache copy -p 6381 --replicate 10.0.0.5:6380 -s
A cache has no password. It serves this machine only, unless created with --public or mutual TLS (--tls --cert --key --ca).

What it does

Redis data types

Strings, lists, sets, hashes, sorted sets, streams; see commands.

Redis features

TTLs, pub/sub and transactions over RESP.

Bounded memory

--maxmemory with an --eviction policy.

Persistence

--persistent file; --persistent-interval journals writes.

Replication

--replicate makes a read-only follower.

Several cores

--shards N, one keyspace; --cluster for cluster-aware clients.

Database backing

Lua on_miss reads through, on_write writes behind; see database backend.

Works with

A server with --cache lets its clients and scripts reach it.
