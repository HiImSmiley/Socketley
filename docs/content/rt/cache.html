A cache is an in-memory data store that speaks RESP2, the Redis protocol, so redis-cli and every Redis client library work against it unchanged; it also answers a plain text protocol for nc and scripts. Strings, lists, sets, hashes, sorted sets and streams with consumer groups, TTLs, pub/sub, transactions, LRU eviction, persistence to a journal, leader-follower replication and a cluster slot map for sharded deployments.

socketley create cache store -p 6379 -s
redis-cli -p 6379 SET greeting hello
redis-cli -p 6379 GET greeting

socketley create cache sessions -p 6380 --maxmemory 512M --eviction allkeys-lru \
    --persistent /var/lib/socketley/sessions.bin -s
socketley create cache copy -p 6381 --replicate 10.0.0.5:6380 -s
A cache has no password. It serves this machine only, unless it is created with --public or given mutual TLS with --tls --cert --key --ca.

What it does

  • Commands: the whole list is the cache protocol, with Redis-compatible spellings over RESP and bridges Redis lacks, such as SCAN … VALUEMATCH, SCAN … TYPE and DBSIZE TYPE.
  • Access: --mode readonly|readwrite|admin for what clients may do; --rate-limit per connection.
  • Memory: --maxmemory with --eviction noeviction|allkeys-lru|allkeys-random; small hashes, lists and sorted sets packed as Redis packs them.
  • Durability: --persistent file journals accepted writes every --persistent-interval and reloads them at start.
  • Replication: --replicate leader makes a read-only follower; see replication.
  • Several cores: --shards N keeps one keyspace over N processes; add --cluster so cluster-aware clients go straight to the owning shard.
  • Lua: on_miss for read-through, on_write/on_delete/on_expire for write-behind to a database backend.
