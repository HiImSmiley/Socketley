A storage serves the S3 API over one directory, so unmodified S3 clients (boto3, the AWS CLI, rclone, every SDK) put, get, list and delete objects on this machine's disk. Around that it keeps what an S3 service keeps: users and IAM policies, versioning, object lock, lifecycle, replication, server-side encryption, event notifications, quotas, website hosting, a cluster of nodes, and a web interface with a drive, share links, media playback and git repositories.

socketley create storage files -p 9000 --dir /srv/objects \
    --credentials /etc/socketley/storage.creds -s
aws --endpoint-url http://127.0.0.1:9000 s3 mb s3://photos
aws --endpoint-url http://127.0.0.1:9000 s3 cp beach.jpg s3://photos/

What it does

  • The S3 API: SigV4 (header and presigned), multipart uploads, path and virtual-hosted addressing, the operations listed, checksums, S3 Select, HTTP/2 and HTTP/3.
  • Who: users from a credentials file, IAM and bucket policies, STS and federated identities, sign-in to the web interface through an idp.
  • Keeping data: versioning, object lock, lifecycle and tiers, replication to other S3 endpoints, a cluster with --nodes, scrub, compression, encryption; --fsync always|interval|never says when an answered write is on disk (durability).
  • Around the data: webhooks per event, bucket websites, quotas, access logs.
  • The web interface: a drive with folders, previews, share links, music and video streamed in renditions, and git repositories over HTTP; see drive, links, media.
  • How it is stored: one file per object version under --dir, described in how objects are stored; performance notes measured against MinIO.

Works with

sync carries directories into it, mail keeps mailboxes in it, metrics archives old blocks to it, and socketley.storage reaches it from Lua.
