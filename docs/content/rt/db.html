A db keeps JSON documents for applications, such as a game's characters or a shop's orders. Each document belongs to an idp account. Nobody writes another account's documents; who may read them is set per collection.

socketley create db data -p 9500 --domain data --idp auth \
    --schema /etc/socketley/db.schema --keys /etc/socketley/db.keys -s
socketley data query characters '{"where":{"level":{"gte":5}},"limit":10}'

What it does

Documents over HTTP

GET, PUT, PATCH, DELETE at /c/collection/id, each versioned for safe writes.

Queries

POST /c/collection/_query filters, sorts and pages on the indexes in --schema.

Access per collection

private, owner, shared, public or catalog; services use --keys.

Transactions and changes

Several writes as one, and a live stream of changes.

Replicas

--replicate keeps a read-only copy of another db.

Backups

Scheduled with --backup-dir, or now with socketley <db> backup|restore.

Works with

Users sign in through an idp. Pictures and other large files belong in a storage.
