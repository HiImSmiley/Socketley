An mcp runtime is a Model Context Protocol server. An AI client such as Claude Code, or an agent built on an MCP SDK, connects to it and is offered the tools, resources and prompts its Lua script declares, and with --tools daemon this daemon's runtimes as tools: listed for every key, started and stopped for an admin's.

printf 'claude %s\nops %s admin\n' "$(openssl rand -hex 16)" "$(openssl rand -hex 16)" > /etc/socketley/mcp.keys
socketley create mcp shop -p 9600 --keys /etc/socketley/mcp.keys \
    --lua shop.lua --tools daemon --instructions "Ask about the shop's orders." -s
claude mcp add --transport http shop http://127.0.0.1:9600/mcp \
    --header "Authorization: Bearer <claude's secret>"

The script declares what is offered:

mcp.tool{
    name = "order_status",
    description = "The state of one order: paid, sent or unknown.",
    read_only = true,
    input = { type = "object", properties = { id = { type = "string" } }, required = { "id" } },
    -- the handler and the rest: examples/mcp/shop.lua in the repository
}

What it does

  • Transport: Streamable HTTP at /mcp, one JSON-RPC message per POST answered as JSON, stateless. It speaks revision 2026-07-28 with its headers, and answers a client that opens with initialize as 2025-11-25, 2025-06-18 or 2025-03-26 do.
  • Who may ask: --keys lists names and secrets, an admin key also changes the daemon; --anonymous for a port only this machine reaches; --origins for browser clients.
  • People, by OAuth: with --idp auth a client that comes without a token is pointed, through /.well-known/oauth-protected-resource/mcp, at the idp runtime, where its person signs in for this server (https://<first --domain>/mcp, a whole name such as mcp.example.com) and allows the client; the idp gives such tokens when its --resources names that address. Members of the idp's admins group are admins here; --idp-audience takes the idp's own clients' tokens as well.
  • What is offered: tools, resources and prompts from the script, and the daemon's runtimes with --tools daemon; --instructions is the text a client is given about the server.
  • Scale: every request is answered on its own, so --shards spreads them over processes; TLS comes from the entrance proxy in front of it.

No benchmark is published for this runtime: there is no established MCP server to measure it against on equal terms.
