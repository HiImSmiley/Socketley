A web runtime serves a site of files to browsers: a documentation site, a blog from a static site generator or a single-page app's build. With --lua-pages its .lua files answer their own addresses, and with --backend php-fpm runs its .php files.

socketley create web docs -p 9500 --root /srv/docs/current --domain docs -s
socketley create web www  -p 9501 --root /var/www/html --domain example.com -s
It speaks plain HTTP and binds 127.0.0.1 unless --bind says otherwise. Visitors reach it through the entrance, which adds TLS and HTTP/2 for its --domain names. No WebSocket, no raw TCP; --tls and --lua are refused, since a script of a web runtime is a page.

What it does

Clean addresses

/guide/ serves guide/index.html, /about serves about.html, and a missing page gets the site's 404.html.

Single-page apps

--fallback index.html answers addresses with no file, while a missing app.js stays a 404.

Lua pages

With --lua-pages, /shop/cart.lua runs shop/cart.lua; what it echoes or returns is the answer. See Lua pages.

PHP

--backend fastcgi://unix:/run/php/php-fpm.sock runs .php files in php-fpm, the answer streamed; the source is never sent.

Releases without a restart

--root may be a symbolic link; swap it to a new build and the next request is served from it.

Caching done right

ETag and Last-Modified on every file; names a build stamped with a hash are cached for a year, pages are revalidated.

Compression

A .br or .gz copy next to a file is sent when the browser takes it; other text files are compressed once and kept.

Nothing leaks

.., links pointing out of --root and hidden files (.env, .git/) are 404, .well-known excepted.

A page in Lua

A page has the socketley functions a script has, and req, echo, header, status, redirect, json, render for .tpl templates, and sessions kept in a cache. It is compiled once and again only when its file changes, so an edit is answered by the next request.

socketley create web site -p 8080 --root /srv/site --lua-pages -s

A program of your own can also take a path of the site, before any file: see the SDK.

Works with

The entrance proxy of a dns runtime gives it HTTPS under its --domain; see the public HTTPS recipe. For a site that also needs WebSocket, use a server with --http.
