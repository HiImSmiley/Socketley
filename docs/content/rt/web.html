A web runtime serves a directory of files to browsers and does nothing else: no script, no WebSocket, no upload. Put a documentation site, a blog from a static site generator or a single-page app's build behind it.

socketley create web docs -p 9500 --root /srv/docs/current --domain docs -s
socketley create web www  -p 9501 --root /var/www/html --domain example.com -s
It speaks plain HTTP and binds 127.0.0.1 unless --bind says otherwise. Visitors reach it through the entrance, which adds TLS and HTTP/2 for its --domain names. --tls and --lua are refused.

What it does

Clean addresses

/guide/ serves guide/index.html, /about serves about.html, and a missing page gets the site's 404.html.

Single-page apps

--fallback index.html answers addresses with no file, while a missing app.js stays a 404.

Releases without a restart

--root may be a symbolic link; swap it to a new build and the next request is served from it.

Caching done right

ETag and Last-Modified on every file; names a build stamped with a hash are cached for a year, pages are revalidated.

Compression

A .br or .gz copy next to a file is sent when the browser takes it; other text files are compressed once and kept.

Never waits on the disk

Small files are kept in memory, large ones sent with sendfile; inotify sees every change at once.

Nothing leaks

.., links pointing out of --root and hidden files (.env, .git/) are 404, .well-known excepted.

Works with

The entrance proxy of a dns runtime gives it HTTPS under its --domain; see the public HTTPS recipe. For a site that also needs WebSocket or a Lua handler, use a server with --http.
