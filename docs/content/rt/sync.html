A sync runtime is one job that carries files between a directory and a storage, out to it, in from it, or both ways. One runtime is one job, so what goes wrong with it has its own line in socketley ls, its own figures, its own log lines and its own alert. It listens on nothing.

socketley create sync photos --dir /srv/photos --storage ui/photos \
    --credentials /etc/socketley/sync.creds --mode out -s
socketley create sync offsite --dir /srv/photos \
    --storage https://files.example.com/photos --credentials /etc/socketley/offsite.creds \
    --every 1h --exclude '*.tmp,.git/*' -s

What it does

  • Where: --storage is a storage runtime and a bucket (ui/photos), a host and port, or any S3 URL, with the bucket last; more than one target is taken only with --mode out.
  • Which way: --mode out mirrors the directory to the bucket, in the bucket to the directory, inout both, a change on either side carried to the other.
  • When: on every change the kernel reports in the directory, and a whole walk every --every to catch what was missed.
  • What: everything below --dir but the --exclude patterns, under --prefix in the bucket.
  • Git: with --repositories it pulls users' git repositories for a storage's web interface.
