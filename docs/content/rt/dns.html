A dns runtime is an authoritative name server: it answers, over UDP and TCP on one port, for the zones it is given and for nothing else. It asks no other server and caches nothing, so a name outside its zones is answered REFUSED and it can never be an open resolver. Given --publish it also answers for the names runtimes carry with --domain, and it proves wildcard certificates for ACME over DNS-01.

socketley create dns ns --zone example.com --publish 203.0.113.7 -s   # writes a zone file to start from
dig @127.0.0.1 example.com SOA
socketley create dns ns2 --zone /etc/socketley/example.com.zone \
    --publish 203.0.113.7 --transfer 203.0.113.53 --notify 203.0.113.53 --dnssec -s

What it does

  • Zone files in RFC 1035 master format: wildcards, CNAMEs followed inside the zone, delegations with glue; an edited file is served within a second.
  • Transport: EDNS with answers kept to 1232 bytes, truncation and retry over TCP, port 53 unless -p says otherwise, IPv4 and IPv6.
  • Secondaries: AXFR to the addresses --transfer names, NOTIFY to those --notify names.
  • DNSSEC with --dnssec: zones signed online, and socketley socketley dns ds prints the DS record for the parentlt;namesocketley dns ds prints the DS record for the parentgt; dnssec prints the DS record for the parent.
  • Abuse: response rate limiting per network with --rrl.
  • Runtimes' names: --publish answers the --domain names of this daemon's runtimes; --proxy makes the entrance those names reach, see names runtimes are reached by.
