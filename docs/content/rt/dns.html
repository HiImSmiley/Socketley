A dns runtime is an authoritative name server for the zones you give it, over UDP and TCP on one port. It answers nothing else and is never an open resolver.

socketley create dns ns --zone example.com --publish 203.0.113.7 -s   # writes a zone file to start from
dig @127.0.0.1 example.com SOA
socketley create dns ns2 --zone /etc/socketley/example.com.zone \
    --publish 203.0.113.7 --transfer 203.0.113.53 --notify 203.0.113.53 --dnssec -s

Good to know first

--publishYour public address. Needed when no interface has one, as behind NAT.
--proxy noneSkips the entrance create makes, which asks Let's Encrypt for certificates. Use it for a lab with real names.
--rrl 0Lifts the default of 100 answers a second per client network, for a load test from one host.

What it does

Zone files

RFC 1035 format; an edited file is served within a second.

UDP and TCP

On port 53 unless -p; large answers move to TCP.

Secondaries

AXFR to --transfer, NOTIFY to --notify.

DNSSEC

--dnssec signs zones; socketley <name> dnssec prints the DS record.

Runtimes' names

Answers for the --domain names of your runtimes (how).

Works with

Its entrance is a proxy. A mail runtime publishes its records through it.
