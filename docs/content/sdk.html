Every runtime type also runs inside a program of your own, from C, Rust, Node or any language that can call C. Its MCP tools, web paths, connections and cache commands can be functions of the program. No daemon is needed. For C++ there are also headers that control a running daemon, or list your own process in it.

The library

Each release has two packages for amd64: socketley is the daemon, socketley-dev the SDK. The SDK package holds libsocketley.so, the header socketley/capi.h and a pkg-config file. It needs no daemon on the machine.

sudo apt install ./socketley-dev_0.2.0_amd64.deb      # from the release's assets
cc app.c $(pkg-config --cflags --libs socketley)

From a checkout, build the socketley_shared target in make/; then sdk/socketley-config --shared --cflags --libs gives the flags.

A smaller library

libsocketley.so holds all fifteen runtime types. A library of only the ones you use is built from a checkout: an MCP server alone is about 13 MB rather than 32.

scripts/premake5 gmake --sdk-runtimes=mcp,web
cd make && make clean && make socketley_shared

Asking such a library for another type is refused by name.

C

An engine is one thread with one io_uring ring; the runtimes created on it share them, and a program may have several. A runtime takes a type, a name and the flags socketley create takes. The engine takes none of the program's signals, writes nothing to its stdout, and answers with return values.

#include <socketley/capi.h>

static void open_thread(void* user, skl_mcp_call* call,
                        const char* args_json, const char* caller)
{
    skl_mcp_reply(call, "opened", 0);   /* now, or later from any thread */
}

char* err = NULL;
skl_engine* e = skl_engine_new(&err);
skl_runtime* site = skl_runtime_create(e, "web", "site",
                        "-p 8080 --root /srv/site", &err);
skl_runtime_start(site, &err);

skl_runtime* tools = skl_runtime_create(e, "mcp", "tools",
                        "-p 9600 --anonymous", &err);
skl_mcp_tool(tools, "open_thread", "Opens a thread.", NULL,
             open_thread, NULL, &err);
skl_runtime_start(tools, &err);
  • Threads. Calls may come from any thread and block until done. A callback runs on the engine's thread and must return quickly; work that takes time goes to a thread of yours, which answers from there.
  • Errors. A function that takes char** err sets it to the reason when it fails; give that text to skl_free.
  • Connections. A connection is a number never given to another, so one that has gone cannot be mistaken for a new one. A client runtime's one stream is always 1.
  • The other runtimes (storage, dns, idp, …) are reached over their own protocol on their port, as any client reaches them.

Rust

The crate in sdk/rust wraps the C interface. It links libsocketley.so from the system's library path, or from SOCKETLEY_LIB_DIR for a checkout's build. A ToolCall may be moved to any thread or task; one dropped unanswered answers as failed.

sdk/rust/examples/mcp_tool.rs, run with cargo run --example mcp_tool -- 9600:

use std::{env, thread, time::Duration};

fn main() -> Result<(), socketley::Error> {
    let port = env::args().nth(1).unwrap_or_else(|| "9600".into());
    let engine = socketley::Engine::new()?;
    let mut tools = engine.runtime("mcp", "tools", &format!("-p {port} --anonymous"))?;

    // Answers at once, on the engine's thread.
    tools.tool("echo", "Gives its arguments back.", None, |call| {
        let text = format!("args {}", call.args());
        call.reply(&text);
    })?;

    // Work that takes time goes to a thread of the program's.
    tools.tool("later", "Answers from another thread.", None, |call| {
        thread::spawn(move || {
            thread::sleep(Duration::from_millis(100));
            call.reply("from a thread");
        });
    })?;

    tools.tool("failing", "Fails.", None, |call| call.fail("it broke"))?;
    tools.tool("silent", "Forgets to answer.", None, |_call| {})?;

    tools.start()?;
    println!("READY {}", socketley::version());
    loop {
        thread::sleep(Duration::from_secs(3600));
    }
}

on_connect, on_disconnect, on_message and send are a server's and client's (echo_server.rs), handle a web runtime's and command a cache's (web_app.rs). To build them against a checkout:

SOCKETLEY_LIB_DIR=$PWD/bin/Release cargo build --examples --manifest-path sdk/rust/Cargo.toml

Node

The package in sdk/node wraps the C interface; its install script builds the addon with node-gyp against libsocketley.so, or the one in SOCKETLEY_LIB_DIR. A handler is an ordinary function on Node's thread, and may be async: what it returns is the answer, and a throw is a failure (a 500 from a web handler).

sdk/node/examples/app.js, a program with its own website, API, cache and MCP tools:

// A program with its own website, API, cache and MCP tools: `node app.js 8080 ./public`, then
//   curl localhost:8080/api/count
//   claude mcp add --transport http app http://127.0.0.1:9600/mcp
const { Engine } = require('socketley');

const port = Number(process.argv[2] || 8080);
const root = require('path').resolve(process.argv[3] || '.');

const engine = new Engine();
const kv = engine.runtime('cache', 'kv', `-p ${port + 1}`).start();
kv.command('set count 0');

const site = engine.runtime('web', 'site', `-p ${port} --root ${root}`);
site.handle('/api/count', () => kv.command('incr count'));
site.start();

const tools = engine.runtime('mcp', 'tools', '-p 9600 --anonymous');
tools.tool('count', { description: 'How often /api/count was asked.' }, () => kv.command('get count'));
tools.start();

process.on('SIGTERM', () => engine.close());
process.on('SIGINT', () => engine.close());

on("connect"|"disconnect"|"message") and send are a server's and client's, handle a web runtime's and command a cache's. A refused flag is a thrown error. The types are in sdk/node/index.d.ts.

C++

The C++ headers in sdk/include/linux/socketley/ come in three tiers. Their examples are in sdk/examples, and the test suite builds each one.

  • Tier 1, control.h: create, start, stop and query the runtimes of a running daemon, over the same socket the CLI uses. Header-only.
  • Tier 2, the engine: server.h, client.h, proxy.h and cache.h with C++ hooks, and any_runtime.h for every other type, linked with libsocketley_sdk.a.
  • Tier 3, attach.h: registers your own process with a running daemon, so socketley ls, stats and ps show it. Header-only.
socketley::any_runtime site("web", "site", "-p 8080 --root /srv/site --lua-pages");
if (!site.start()) return 1;

The runtimes are Linux only

The engine is built on io_uring, so the runtimes run on Linux, with or without the daemon. For Windows and macOS there are header-only clients, ws_client.h and cache_client.h, which reach a socketley on Linux over the network.
