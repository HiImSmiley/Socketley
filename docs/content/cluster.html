Several daemons, on one machine or many, form a cluster by sharing a directory: each writes its state there every two seconds and reads the others', and a daemon whose heartbeat is older than ten seconds is left out. From then on socketley ls on any of them shows every daemon's runtimes, a proxy's @group backend reaches the group's members wherever they run, and scripts are told when daemons and groups change.

# on every machine, the same shared directory
socketley daemon --name node-a --cluster /mnt/cluster
socketley create server api -p 9000 -g api -s
# anywhere in the cluster
socketley create proxy gw -p 8080 --backend @api -s
socketley daemons
Whoever can write to the cluster directory decides where a proxy's @group traffic goes. Give it the same protection as the daemon's control socket.

Service mesh

The proxy's resilience features, health checks, circuit breaker, deadlines, retries and mTLS, are what a service mesh gives each call; --sidecar puts a proxy beside one service with all of them on.
