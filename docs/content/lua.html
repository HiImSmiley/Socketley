A runtime created with --lua file runs that script in its worker: LuaJIT, Lua 5.1 syntax, with the runtime as self. The script is loaded at start and replaced in place with socketley reload-lua name, connections kept. Callbacks are plain global functions; a runtime calls those its type has.

-- a server that answers each line, counts clients and says the time every minute
local n = 0
function on_connect(id)    n = n + 1 end
function on_disconnect(id) n = n - 1 end
function on_client_message(id, msg)
    self.send(id, "you said: " .. msg)
end
socketley.set_interval(60000, function()
    self.broadcast(os.date("%H:%M") .. ", " .. n .. " online")
end)
A callback runs on the runtime's only thread. Everything here that waits does so without blocking it, and socketley.http does in a callback that can wait, such as an mcp tool's handler; anywhere else it blocks the loop until its exchange ends, as its entry says. Every callback runs under a deadline, so one that loops for ever is ended and the runtime goes on; see Callback Deadline below.
