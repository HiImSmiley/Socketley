A runtime created with --lua file runs that script: LuaJIT, Lua 5.1 syntax, the runtime as self, callbacks as global functions. It loads at start; socketley reload-lua name replaces it and keeps connections.

-- a server that answers each line, counts clients and says the time every minute
local n = 0
function on_connect(id)    n = n + 1 end
function on_disconnect(id) n = n - 1 end
function on_client_message(id, msg)
    self.send(id, "you said: " .. msg)
end
socketley.set_interval(60000, function()
    self.broadcast(os.date("%H:%M") .. ", " .. n .. " online")
end)
Callbacks run on the runtime's single thread. Inside a callback that can wait, such as on_message, on_client_message or an mcp tool's handler, socketley.http waits without blocking that thread. Anywhere else it blocks the whole runtime until the answer arrives. A callback that never ends is stopped by its deadline.
