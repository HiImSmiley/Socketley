Ten minutes, three runtimes. Every command here works against a fresh install; nothing has to be written to a file except one short script.

1. A server

socketley create server chat -p 9000 -s
socketley ls

create makes a runtime and -s starts it at once. Open two terminals with nc 127.0.0.1 9000: a line typed in one appears in the other, because a server without a script relays what each client says to the others. socketley send chat "hello" sends to all of them from the CLI.

2. A script

Write echo.lua:

function on_client_message(id, msg)
    self.send(id, "you said: " .. msg)
end
socketley create server echo -p 9001 --lua echo.lua -s
printf 'hi\n' | nc -q1 127.0.0.1 9001

on_client_message is told who spoke, and self.send(id, …) answers that connection. Edit the file and run socketley reload-lua echo; connections stay open. Every callback and method is on the Lua page.

3. A cache

socketley create cache store -p 6379 -s
redis-cli -p 6379 SET visits 0
redis-cli -p 6379 INCR visits

The cache speaks the Redis protocol, so redis-cli and any Redis library work. It also answers plain text: printf 'get visits\n' | nc -q1 127.0.0.1 6379.

4. A proxy

socketley create server web -p 9100 --http ./site -s
socketley create proxy gw -p 8080 --backend web -s
curl http://127.0.0.1:8080/gw/index.html

The backend is named by its runtime name, so the proxy follows it if its port changes. A request to /gw/... reaches the backend as /...; give the proxy --domain names and put it behind the entrance to serve sites under their own names with certificates.

5. Look at it

socketley ls                 # every runtime, its state and port
socketley stats gw           # live counters
socketley show echo          # its configuration as JSON
socketley edit gw --backend-timeout 5s --restart
socketley stop chat; socketley remove chat

Restart the daemon (sudo systemctl restart socketley): every runtime that was running comes back by itself. The dashboard shows the same in a browser.
