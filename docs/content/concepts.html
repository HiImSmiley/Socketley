The rules every runtime follows, whatever its type. For what happens behind a command, step by step, see How it works.

A runtime

A runtime is one network service. It has a type, which decides what it speaks (a server, a proxy, a cache, …; see registered types), and a name, unique on its daemon, by which commands and other runtimes refer to it.

CommandWhat it does to a runtime
create type name [flags]Checks the flags and saves the runtime. With -s it also starts it.
start / stopStarts its worker process / ends it. The runtime itself is kept.
edit name [flags]Changes flags. Without flags it opens the runtime's JSON in your editor.
reload-lua nameLoads the changed script without dropping connections.
removeStops it and deletes it.

A runtime is always in one of four states: created (saved, never started), running, stopped, or failed (it could not start; ls shows why).

State that survives

Each runtime is saved as a JSON file in the daemon's state directory. When the daemon starts, it brings every runtime back and starts the ones that were running before. Runtimes survive restarts and reboots without any setup.

CommandUse it to
show name / import namePrint a runtime's configuration as JSON / replace it from JSON, so show a | import b copies one.
export dirWrite the daemon's whole setup as Lua files into a directory.
export --full fileArchive setup and data together, for a backup; restore puts it back.

Names, ports and addresses

  • Runtimes find each other by name. --backend api or --cache store names a runtime, not a port, so the link holds when its port changes.
  • Public names go through the entrance. A runtime's --domain names are served by the entrance, the one proxy on ports 80 and 443, which also gets their certificates.
  • A port can be kept local. --bind 127.0.0.1 binds it to one address; --listen unix:/path uses a unix socket instead of a port.
  • One address, one runtime. Two runtimes on the same port and address are refused, so a typo cannot silently split traffic.

TLS

A server, cache, proxy or mqtt broker encrypts its own port with --tls --cert file --key file. Add --ca file to require client certificates. --acme name gets a Let's Encrypt certificate and renews it.

When socketley connects out (a client runtime, a proxy's https:// backend), it always verifies the server's certificate; that check cannot be turned off. What is not supported is listed under TLS limitations.

Several cores

A runtime's worker uses one core. --shards N runs N workers that share the port, and --cpus chooses the cores they may run on. On a cache, each key belongs to one shard. More shards do not always mean more speed: read sharding before choosing N.

Scripts

Most types take --lua file: a script whose callbacks (on_client_message, on_http_request, …) answer instead of the built-in behaviour. It is loaded when the runtime starts and replaced with reload-lua. A callback that never returns is ended by its deadline. See Lua scripting.

More than one machine

Daemons that share a cluster directory see each other's runtimes, and a proxy's @group backend reaches group members on every machine. See Cluster.

Watching it

socketley ls lists runtimes and their states; socketley stats name and socketley daemon stats print live counters. The daemon also serves a web dashboard and Prometheus /metrics. A metrics runtime keeps the history and sends alerts.
