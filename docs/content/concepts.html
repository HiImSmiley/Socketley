The daemon and the CLI

One binary is both. socketley daemon holds the runtimes and listens on a unix socket (/run/socketley/socketley.sock when installed, /tmp/socketley.sock in development); every other invocation is a CLI that sends the daemon one command and prints its answer. Success is silent, errors go to stdout, and the exit status is 0, 1 for bad input or 2 for a fatal error.

A runtime

A runtime has a type (one of the registered types), a name unique on the daemon and a six-character id. It is made with create, which checks every flag and keeps the configuration, and runs from start, which is also when its Lua script is loaded. Its life is created → running → stopped, or failed with the reason in ls and the log.

Every runtime is its own process. The daemon forks a supervised worker per runtime (per shard, with --shards), so a crash or a runaway script takes one runtime down and not the daemon; it is restarted, counted, and a worker stuck in a busy loop is reported. Each worker runs one io_uring event loop on one thread.

State that survives

Each runtime's configuration is a JSON file in the state directory. When the daemon starts it restores every runtime and starts the ones that were running when it stopped, so a reboot brings the whole topology back. show prints the JSON, edit changes flags, import replaces the configuration, export writes all of it, and export --full archives state and data together for a backup.

Names, ports and addresses

Runtimes reach each other by name: a proxy's --backend api, a server's --cache store, a mail runtime's --storage files/mail. A runtime with --domain names is served by the entrance, the one proxy on 80 and 443, under those names with certificates it obtains itself, and a dns runtime with --publish answers for them. --bind keeps a port to one address, --listen unix:/path trades the port for a unix socket, which is faster and checked by file permissions.

TLS

TLS terminates on a server, cache, proxy or mqtt listener with --tls --cert --key, verifies client certificates with --ca, and a client or a proxy's https:// backend dials over verified TLS; there is no switch to skip verification. --acme gets and renews Let's Encrypt certificates. See TLS under limitations for what is not supported.

Several cores

A runtime's worker is one thread. --shards N runs N workers that share the port through SO_REUSEPORT; on a server or proxy any shard answers any request, on a cache each key has one owning shard and --cluster lets clients go to it directly. --cpus pins where the I/O runs. Read the sharding section before choosing N: the gain depends on the workload, and it is measured there.

Scripts

Most types take --lua file: callbacks the runtime calls on its events and methods it offers back. The script is loaded at start, replaced with reload-lua, and runs under a deadline so a runaway callback ends instead of stalling the runtime. See Lua scripting.

More than one machine

Daemons that share a directory, typically a volume between containers, discover each other through it: ls shows every daemon's runtimes, @group backends span machines, and scripts are told when daemons join and leave. An opt-in Raft mode replicates the cluster's state. See Cluster.

Watching it

socketley stats prints a runtime's live counters, daemon stats the daemon's. The daemon serves a dashboard in the browser and a Prometheus /metrics endpoint, and a metrics runtime keeps the history, raises alerts and sends them by webhook or mail.
