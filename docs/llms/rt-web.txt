# web runtime

Static site of files for browsers: a docs site, a blog, a single-page app; caching and compression built in

A **web** runtime serves a directory of files to browsers and does nothing else: no script, no WebSocket, no upload. Put a documentation site, a blog from a static site generator or a single-page app's build behind it.

```
socketley create web docs -p 9500 --root /srv/docs/current --domain docs -s
socketley create web www  -p 9501 --root /var/www/html --domain example.com -s
```

> It speaks plain HTTP and binds `127.0.0.1` unless `--bind` says otherwise. Visitors reach it through the entrance, which adds TLS and HTTP/2 for its `--domain` names. `--tls` and `--lua` are refused.

## What it does

- **Clean addresses**: `/guide/` serves `guide/index.html`, `/about` serves `about.html`, and a missing page gets the site's `404.html`.
- **Single-page apps**: `--fallback index.html` answers addresses with no file, while a missing `app.js` stays a 404.
- **Releases without a restart**: `--root` may be a symbolic link; swap it to a new build and the next request is served from it.
- **Caching done right**: ETag and Last-Modified on every file; names a build stamped with a hash are cached for a year, pages are revalidated.
- **Compression**: A `.br` or `.gz` copy next to a file is sent when the browser takes it; other text files are compressed once and kept.
- **Never waits on the disk**: Small files are kept in memory, large ones sent with `sendfile`; inotify sees every change at once.
- **Nothing leaks**: `..`, links pointing out of `--root` and hidden files (`.env`, `.git/`) are 404, `.well-known` excepted.

## Works with

The entrance [proxy](rt-proxy.txt) of a [dns](rt-dns.txt) runtime gives it HTTPS under its `--domain`; see the [public HTTPS recipe](deploy.txt). For a site that also needs WebSocket or a Lua handler, use a [server](rt-server.txt) with `--http`.

## Flags

Every flag a web runtime takes, by group.

**Basics**

| flag | value | what it does |
|---|---|---|
| `-p` | int | Port: The port it listens on (a client: the port of its target). |
| `-s` |  | Start now: Start it as soon as it is made. |
| `--lua-ffi` |  | Lua FFI: Let the script require("ffi"): LuaJIT's calls into C and raw memory, where a wrong pointer ends the runtime's process. |

**Network**

| flag | value | what it does |
|---|---|---|
| `--bind` | text | Bind address: Bind the port to this address only, such as 127.0.0.1 when only a proxy on this machine should reach it. |
| `--shards` | int | Shards: Worker processes sharing the port: the way one runtime uses more than one core. |
| `--domain` | list | Names: The names it is reached by through the entrance; empty for its own name. |
| `--cpus` | text | CPUs: The CPUs its I/O may run on, as 0-3,6. |

**Limits**

| flag | value | what it does |
|---|---|---|
| `--max-connections` (--max-conn) | int | Max connections: The most clients at once. |

**Output**

| flag | value | what it does |
|---|---|---|
| `--log` | path | State log: A file it appends each state change to. |

**Web**

| flag | value | what it does |
|---|---|---|
| `--root` | path | Document root: The directory whose files are the site. Required. |
| `--index` | text | Index page: The file a directory's address is answered with, index.html unless given. |
| `--fallback` | text | Fallback page: The page an address with no file is given, with 200, as a single-page app routes; 404.html, if there, otherwise. |
| `--backend` | text | PHP server: The FastCGI server a .php file under --root is run by: fastcgi://unix:/path or fastcgi://a.b.c.d:port. |
| `--fastcgi-root` | path | Server's root: --root as the FastCGI server sees it, when that is another path (a container). |
| `--lua-pages` |  | Lua pages: Run a .lua file under --root as a page, which answers its own address, rather than serving it. |

## Benchmarks

A ratio (×) is how many times better socketley did: more per second, or less time, memory or CPU; above 1× socketley is ahead. The range in brackets is the lowest and highest ratio across the passes.

### Static site: pages, assets, compression, revalidation

nginx 1.28.3, 3 passes, 2026-11-10, socketley 0174a7a1.

| case | socketley | nginx | socketley vs nginx |
|---|---|---|---|
| page 4 KiB, keep-alive, 256 connections | 237 K req/s (1.00 cores) | 48 K req/s (1.00 cores) | 4.94× (4.68–4.97) |
| page 4 KiB, a connection per request, 64 at once | 80 K req/s (1.00 cores) | 32 K req/s (1.00 cores) | 2.50× (2.46–2.74) |
| asset 64 KiB (hashed name), keep-alive, 256 connections | 81 K req/s (0.99 cores) | 42 K req/s (1.00 cores) | 1.89× (1.73–2.24) |
| file 1 MiB, keep-alive, 64 connections | 25 K req/s (1.00 cores) | 21 K req/s (1.00 cores) | 1.22× (1.16–1.24) |
| page 4 KiB as gzip, the .gz beside it | 272 K req/s (1.00 cores) | 48 K req/s (1.00 cores) | 5.66× (5.26–5.99) |
| page 4 KiB as brotli, the .br beside it | 277 K req/s (1.00 cores) | 47 K req/s (1.00 cores) | 5.99× (5.83–6.07) |
| page 4 KiB as gzip, no .gz on disk | 275 K req/s (1.00 cores) | 25 K req/s (1.00 cores) | 10.95× (10.69–11.06) |
| revalidation: If-None-Match, 304 | 283 K req/s (1.00 cores) | 59 K req/s (1.00 cores) | 4.73× (4.66–4.84) |
| missing file: the site's 404.html | 248 K req/s (1.00 cores) | 40 K req/s (1.00 cores) | 6.14× (6.13–6.25) |
| 10,000 pages of 4 KiB at random | 237 K req/s (1.00 cores) | 52 K req/s (1.00 cores) | 4.58× (4.57–4.85) |

How it was measured: wrk 8 threads, 4 s a run; each server on one core, wrk (8 threads) on 20 others. socketley create web --root with its defaults against nginx with one worker, sendfile, open_file_cache, gzip_static and brotli_static, both sending the same headers on plain HTTP (TLS and HTTP/2 are the entrance proxy's). The compressed rows send the same .gz and .br bytes; in the row with no .gz on disk socketley sends a copy it made once and nginx compresses every answer, so that row shows what each does with a site deployed without copies rather than a like-for-like speed. This VM halts idle vCPUs, which costs a server that writes each answer on its own more than one that batches: a single unpublished pass on another VM (16 cores) read 1.72x for the headline row. The kernel keeps at most 2,048 connections in TIME-WAIT for every arm (net.ipv4.tcp_max_tw_buckets, 131,072 by default), so a pass with a connection per request does not wait out the closed connections of the one before.
