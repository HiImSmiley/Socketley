# Lua configuration

From the manual page socketley(1).

**Two different files are both called “a Lua script”, and they do not mix.**

- A *daemon configuration* — **socketley --lua config.lua**. This file runs in the CLI process. The CLI reads its **daemon** and **runtimes** tables, brings the daemon to what they say, and exits. The daemon reads the same tables from its own configuration file when it starts. This file never becomes part of any runtime. A callback defined in it is dead code: nothing loads it, nothing calls it, and nothing reports it.
- A *runtime handler* — **socketley create server api -p 9000 --lua handler.lua**, or the same path given as a runtime's **config** key inside a configuration. The daemon loads this file into that runtime's own interpreter. It is the only file whose **on_*** callbacks, **filters** and **routes** mean anything.

A configuration attaches a handler by naming its path. It never defines the callbacks itself:

```
runtimes = {
    { type = "server", name = "api", port = 9000,
      config = "handler.lua",     -- the file whose callbacks run
      start = true },
}
```

**config** and **lua** are two accepted spellings of the same key. Everything below this point in this chapter, except **Configuration File Format** itself, describes a *runtime handler*.

**Module loading:** The Lua **require()** function resolves modules relative to the script's directory. For a script at */home/user/handler.lua*, **require("utils")** loads */home/user/utils.lua*. The default Lua package path is appended, so standard modules still work.

**Standard library:** **base**, **string**, **table**, **math**, **os**, **io** and **package** are open. Two **os** functions are removed, because each one damages the process that every runtime shares: **os.exit** and **os.setlocale**. **os.execute**, **os.remove**, **os.rename** and **os.tmpname** are present (see **Handler Privileges**).

**os.setlocale** is removed for a reason of its own. **setlocale** is process-wide. **socketley.json_encode** formats numbers with **%.14g**, and **socketley.json_decode** parses them with **strtod**, and both read **LC_NUMERIC**. If one script switches to a comma-decimal locale, *every* runtime in the daemon emits **1,5** and truncates **1.5** to **1**, for as long as the daemon lives. **os.time**, **os.clock**, **os.date** and **os.difftime** stay, because they only read.

## Configuration File Format

```
-- Optional: configure the daemon itself
daemon = {
    name = "node1",
    cluster = "/shared/cluster"
}

runtimes = {
    { type = "server", name = "api", port = 9000, group = "api",
      config = "handler.lua", start = true },
    { type = "client", name = "cli", port = 9000, target = "127.0.0.1:9000" },
    { type = "proxy",  name = "gw", port = 8080,
      backends = {"@api", "127.0.0.1:9000"}, strategy = "round-robin" },
    { type = "cache",  name = "store", port = 9001,
      persistent = "/data/store.bin" }
}
```

The **daemon** table is processed first (name, then cluster). If it is omitted, the daemon runs without cluster mode.

The daemon itself reads this table's keys (**name**, **cluster**, **log_level**, **metrics_port** and **cpus**) at startup, from the file that **SOCKETLEY_CONFIG** names. The last three are settled before the ring exists, and cannot be told to a daemon that is already serving. **socketley --lua** therefore refuses them by name rather than dropping them. The exception is the daemon's own file, where they take effect at the daemon's next start. A flag typed on **socketley daemon** outranks the same setting in the file. **config** is the older name of this table and still works. A file that names both is refused.

The recognised **runtimes** keys, and the flag each one becomes, are listed below. Every flag that **create** accepts can be set from here. A configuration file and a command line are therefore two ways to write the same thing, not two different capabilities:

Every other flag of a type has a key of the same name, without the leading dashes and with each hyphen turned into an underscore: **--mail-domain** is **mail_domain**, **--submission** is **submission**, and **--queue-lifetime** is **queue_lifetime**. A list key takes a table, or one string for a list of one. A key that no flag of the type has is refused by name, not silently dropped. A value of the wrong shape is refused the same way. So is a value that contains a tab, because the daemon's command line splits on tabs. A password containing a tab would arrive as two arguments. A space stays inside its value, as it does inside a quoted argument on the command line.

A key can pass this check and still be refused by the daemon for that type, such as **--client-ca** on a cleartext proxy. The daemon's own error is then shown under the name of the runtime the key belongs to. The remaining entries are still applied, and the exit code is 1.

The **daemon_process** key has been removed, together with the flag it produced. A configuration file that still contains it is refused, naming the line. The key is not silently dropped, because that would leave an operator believing a runtime is in the daemon when it is not.

Nothing replaces it, because the whole cross-runtime API works in a worker:

- **socketley.send**, **.list**, **.get** and **socketley.cluster** are answered from the replica map that the daemon pushes.
- **socketley.create**, **.start**, **.stop** and **.remove** are sent to the daemon, and wait for its answer.
- **socketley.pipe** and **self.route** reach a runtime in another process.

See **Process Isolation** above.

The health-check, circuit-breaker, retry and TLS keys were added when the table above was made to name every flag. A file written before then still reads the same way.

The interpreter that reads a configuration file is not the daemon's, and it is much smaller. It opens **base**, **package**, **table**, **string** and **math**. There is no **os** and no **io**. So `**os.execute("mkdir -p /tmp/logs")**` at the top of a configuration is not a sandbox refusal. It fails with **attempt to index global 'os' (a nil value)**: the whole file is refused, the exit code is 1, and no runtime is created. Create the directories that a configuration needs from the shell that runs it. **string** and **math** are open because a configuration computes names and port numbers. The daemon's own configuration file opens the same set, so either interpreter can read the same file.

## A machine's setup

A setup is a machine's runtimes, written as Lua files. Another machine that is given the files gets the same runtimes. The runtimes' data is not in the files.

**include** reads a file and returns what that file returns. Given a directory, it reads each **.lua** file in it, in name order, and returns the list of their results. A list inside **runtimes** is expanded into its entries. A relative path is resolved beside the first file, wherever the command was typed. This applies to an include's path and to a path value, such as a credentials file, a certificate, a handler script or a zone file:

```
-- /etc/socketley/config.lua
daemon = { metrics_port = 9190, dashboard_idp = "auth" }
runtimes = {
    include "runtimes/ns.lua",
    include "runtimes/auth.lua",
    include "runtimes/sites",            -- every .lua in it
}

-- /etc/socketley/runtimes/ns.lua
return { type = "dns", name = "ns", zone = { "zones/example.com.zone" },
         publish = { "203.0.113.7" }, start = true }
```

**socketley --lua** brings the daemon to what the files say:

- A runtime that the daemon does not have is created.
- For a runtime that the daemon has, the CLI plans it as **create** would make it from the file, and compares the plan with what **show** reports. Where they differ, the runtime is told what differs, across a restart if it is running, and is then asked again. A setting that the file no longer contains is cleared. A runtime that does not take a setting is named, and the exit code is 1.
- A runtime that already matches the file is not touched.
- **start** starts or stops the runtime. A runtime without **start** is left running or stopped, as it is.
- A runtime of the daemon's that the files do not name is left alone.

When the daemon starts, it reads the **runtimes** of its own configuration file, after restoring the runtimes it kept. It creates each runtime it does not have, and starts it where **start** says so. A runtime that it already has is left as it is, for **socketley --lua** to bring in line with the file. A new machine therefore needs only the files in **/etc/socketley**; nothing else has to be run. **socketley export** writes a running machine's setup in this form.

## Handler Privileges

**A Lua handler runs with the daemon's full privileges.** It is not sandboxed, and there is no supported way to sandbox it. Read a handler as you would read a program you are about to run as the daemon's user, because that is exactly what it is.

This makes the control socket's permission the whole security boundary. A handler is attached with **create --lua**, which is an ordinary command on that socket. Anyone who may open the socket may therefore run code as the daemon's user. The socket is **0600** for a daemon you start yourself, and **0660 socketley:socketley** for the packaged one. Membership of that group is therefore equivalent to being the daemon's user, and should be granted on that understanding. Docker uses the same arrangement. It is stated here so that nobody has to infer it: nothing else in this daemon stands between a local account and the handler.

Concretely, a handler can:

#### `run any command`

**io.popen("...")** and **os.execute("...")** are both present.

#### `read or write any file that user can`

**io.open()** is present in every mode, including **w**, which truncates.

#### `load native code`

**package.loadlib()** is present, as are **load**(), **loadstring**(), **dofile()** and **loadfile**().

#### `read the daemon's environment`

**os.getenv()** is present.

This is deliberate. Handlers legitimately read and write files. A logging pipeline appends to one, and a configuration-driven handler reads its table from disk. Closing **io** would therefore break supported use. In practice, **the right to hand this daemon a --lua script is the right to run code as its user.** The permission on the IPC socket controls that right, not anything in the interpreter. See **THE IPC SOCKET** under **FILES**.

A handler's interpreter opens **base**, **string**, **table**, **math**, **os**, **io** and **package**. Two names are removed from **os**. Calling either one fails with **attempt to call field '...' (a nil value)**, not with a refusal that gives a reason:

```
os.exit    os.setlocale
```

Neither removal is a security boundary; nothing here is. Both pass a narrower test. Each is a call that damages the process that every *other* runtime in this daemon shares, and that a script makes by accident rather than by intent.

- **os.exit()** ends the daemon from inside a callback. A handler is very often a standalone script that grew into one, and it ends the way standalone scripts end.
- **os.setlocale()** changes the process's **LC_NUMERIC**. **socketley.json_encode** and **socketley.json_decode** use it to format and parse numbers. One line in one handler makes every other handler's JSON write 1.5 as 1,5 and decode it as 1. This happens silently, for as long as the daemon lives.

**os.time**(), **os.clock**(), **os.date**() and **os.difftime**() remain: they only read, and reading the clock or the locale harms nothing.

**os.execute**(), **os.remove**(), **os.rename**() and **os.tmpname**() are present. Removing them would deny no capability, because **io.popen** is a shell and **io.open(path, "w")** truncates. It would only suggest, to anyone reading a handler, that the daemon guards its files and its shell, which it does not. A fence with an open gate beside it is worse than no fence, because people plan around it.

**io.open** and every write through it block the event loop for as long as the write takes.

**require()** resolves against the script's directory, and then against the default **package.path**. **package.cpath** is left at its default, and no binary module ships with socketley. A **require** of a C module, such as **cjson**, **lsqlite3** or a **luasql** driver, therefore fails unless that module is installed where the system Lua would find it. For JSON, use the built-in **socketley.json_encode** and **socketley.json_decode** instead; they need nothing installed.

## Available Callbacks

#### `on_start()`

Called when the runtime starts.

#### `on_stop()`

Called when the runtime stops.

#### `on_message(msg)`

Called when a message is received (server and client). A client passes the connection id as a second argument, 1 unless **--connections** is given; see there. When a server defines this callback, it takes over message handling: the default broadcast (in **inout** and **master** modes) is suppressed. Use **self.broadcast(msg)** to relay messages yourself.

#### `on_client_message(client_id, msg) -> true`

Called when a message is received, with the sender's id (server only). It fires alongside on_message, and first. Returning **true** says the script has handled the message, so nothing is sent automatically: not the relay of **--mode inout** or of the master's messages, and not what **--send-to** names for a non-master. Returning anything else, or nothing, leaves those as they are. On a UDP server, client_id names the peer that sent the datagram; see **--udp**. A handler still waiting on **self.cache** when the relay runs has not returned yet, so its message is relayed; define on_message to stop the relay for such a script.

#### `on_messages(chunk, id)` / `on_client_messages(client_id, chunk) -> true`

The batch forms of on_message (client) and on_client_message (server): every complete line of one read in one call, instead of one call per line. **chunk** is the bytes as they arrived, up to and including the read's last newline, so every line in it ends with its '\n', a CRLF line keeps its '\r' and an empty line is a bare '\n'. An unfinished last line is kept and arrives at the start of the next call. When a script defines both forms, only the batch one is called.

A client calls on_messages for its TCP, unix-socket and TLS reads, with the connection's id after the chunk (see **--connections**). A server calls on_client_messages for a TCP line connection; returning **true** answers for every line in the chunk, as on_client_message's **true** does for one. A route or pipe the script sets from on_client_messages carries the next read on: the lines of the chunk it was handed are its own and are not sent on as well. Where there is no read to batch, each message is a chunk of one line with its '\n' added, and a message that itself holds a newline reads as more than one line there, so a script for such a runtime is better written with on_message: a datagram (**--udp**), a WebSocket message, a server in **--mode master** or with **--rate-limit** or **--global-rate-limit**, which judge each line on its own. **-w**, bash output and an interactive attach still see each line, exactly as with on_message.

A call per read instead of per line pays where the script takes the chunk whole: measured on one core, a server echoing 64 connections of 16 pipelined 64-byte lines with one **self.send** per chunk answered 1.6 times as many as with on_client_message. A script that walks the chunk line by line in Lua spends about what the calls it saves cost: counting 64-byte lines with string.find as below came to 5 per cent fewer than with on_message, and with 4 KiB lines, where copying the chunk into Lua is the cost, a third fewer. Counting the lines of a chunk:

```
local n = 0
function on_messages(chunk)
    local i = 1
    while true do
        local j = string.find(chunk, "\n", i, true)
        if not j then break end
        n = n + 1      -- the line is chunk:sub(i, j - 1)
        i = j + 1
    end
end
```

#### `on_http_body(client_id, chunk, remaining)`

Called with each piece of a request body and the number of bytes still to come after it. **remaining** therefore reaches 0 exactly once per body. Defining this callback is the opt-in. A server whose script defines it streams request bodies to the callback instead of collecting them. A server whose script does not define it keeps its usual behaviour, including the 413 for a body larger than **--read-buffer**.

This callback is what makes a body larger than memory possible. The bytes are handed over and erased as they arrive. So **req.body** in the **on_http_request** that follows is deliberately EMPTY: keeping the bytes a second time is the memory cost this callback exists to avoid. Measured on one worker, one connection at a time:

```
start             19,796 kB
after 50 MB #1    37,344 kB
after 50 MB #2    37,344 kB     unchanged
after 50 MB #3    37,344 kB     unchanged
after 200 MB      37,428 kB     +84 kB
after 500 MB      37,444 kB     +16 kB
```

The first upload costs 17.5 MB once, which is the provided-buffer ring being faulted in. Every upload after it costs nothing: half a gigabyte is received inside 37 MB resident.

Keep per-upload state keyed by **client_id**, and clear it in **on_disconnect**. An abandoned body never reaches **on_http_request**, so nothing there can reset the state. **on_disconnect** is the only signal an abandoned body produces. It does fire, however much of the body arrived. That is what a script writing to a temporary file needs in order to remove the file.

```
local st = {}
function on_http_body(id, chunk, remaining)
    st[id] = (st[id] or 0) + #chunk
    if remaining == 0 then ... end
end
function on_disconnect(id) st[id] = nil end
```

**A body of unknown length.** A client that cannot say how long its body is sends **Transfer-Encoding: chunked**. Examples are fetch() with a ReadableStream body, anything piping a process's output, and anything that cannot stat what it is sending. With **on_http_body** defined, such a body is decoded and delivered like any other, without a limit, because there is no length to limit it by. Without the callback, it is answered 501.

**remaining** is **nil** for every chunk of such a body, because how much is still to come is genuinely unknowable. The end of the framing produces ONE final call, with an empty chunk and **remaining = 0**. So "remaining reaches 0 exactly once per body" holds for both forms, and a script written for **Content-Length** needs no change. Measured with 62 MB in 1000 chunks: 1708 calls, 1707 of them nil and one zero. 250 MB more after that costs 148 kB more resident memory.

Only chunked is decoded. **Transfer-Encoding: gzip, chunked** can be framed, because the chunk sizes do delimit it, but its contents are still compressed. Removing the framing and handing the bytes on as the body would hand on gzip and call it the body. That stays 501. A coding that is not chunked at all leaves the message with no way to say where the body ends, and is answered 400.

Trailers are consumed, limited to 8 KB, and discarded. Turning them into headers after the request has been dispatched is how a trailer becomes request smuggling. Framing that contradicts itself is a 400, because nothing after it can be trusted to be payload. Examples are a chunk not followed by CRLF, a size that is not hex, and a size line longer than 256 bytes.

Header names keep the case the client sent them in, so use **req.headers["Host"]** and not **req.headers["host"]**.

#### `on_upstream_writable(conn_id)`

Called when an upstream's write queue has come back under **self.watermark()**. A producer that stopped because **self.upstream_pending(conn_id)** was high can then carry on. This is a separate callback from **on_writable** because upstream ids and client ids are different spaces. One function taking both would have to be told which kind of id it had been given.

#### `on_writable(client_id)`

Called when this connection's write queue has come back under **self.watermark()**. A producer that stopped because **self.pending(client_id)** was high can then carry on. The callback is edge-triggered: it fires once per crossing, not once per completed write.

A client runtime passes its connection id, **on_writable(id)**. It is 1 unless **--connections** is given. A client's refusal to send also names its real cause. A connected **--mode out** client whose server has stopped reading is refused with a reason that names the backlog. It is not told it "is not connected to its server, or was created --mode in and does not send", three statements that are all false of it. Measured with 400 chunks of 64 KB sent to a peer reading nothing: 129 taken, 271 refused, 8,396,928 bytes queued.

This callback is what makes a body larger than the queue limit sendable at all. Without it, a script had only the hard limit, with nothing leading up to it: at 8 MiB the connection is closed. The only safe strategy was to know the limit in advance and never approach it. Measured with a client reading in 256 KB bites with a 5 ms pause, sending 200 chunks of 64 KB (13,107,400 bytes):

```
unpaced   8,454,273 bytes delivered, then the connection closed
paced    13,107,400 bytes delivered, on_writable fired 3 times
```

Pace against **self.watermark()**, not against a number of your own. It is a call and not a field because **--write-buffer** can be edited, and a number copied into the script's table at load would go stale as soon as the setting changed. The callback fires on the crossing. A producer that stops below the watermark never crosses it, so it is never called back. It would wait for an event that its own caution prevented:

```
local function pump(id)
    while remaining > 0 do
        if (self.pending(id) or 0) >= self.watermark() then return end
        if not self.send(id, next_chunk()) then return end
        remaining = remaining - 1
    end
end

function on_writable(id) pump(id) end
```

The call is made one loop turn after the write that emptied the queue, not on that write's completion. A connection that closes in between is simply not called.

#### `on_connect(client_id)`

Called when a client connects (server and client). It is also called on a sub-server when a connection is routed to it. The client_id is opaque. For this runtime's own clients, it is the file descriptor. For a connection routed here from another runtime, it is a handle above 16777216 that names the connection wherever it lives. Pass it back to **self.send()**, **self.owner_send()**, or anything else that takes a client_id. Do not compare it against a descriptor or assume anything about its value.

#### `on_disconnect(client_id)`

Called when a client disconnects (server and client). A client's **on_connect** and **on_disconnect** are given the descriptor and then the connection id; see **--connections**.

#### `on_rcpt(rcpt, default) -> bool`

Decides, in a mail runtime, whether to accept each recipient as the client names it. Each message the runtime accepts is then passed to **on_message(msg)**. See **Lua** under **MAIL FLAGS**.

#### `on_publish(client, msg) -> bool | table` / `on_subscribe(client, filter, qos) -> bool`

Decide, in an mqtt runtime, which publishes and subscriptions pass. In that runtime, **on_auth**, **on_connect** and **on_disconnect** are given a client table. See **Lua** under **MQTT FLAGS**.

#### `on_send(msg)`

Called when a message is sent. Under **--shards**, it is called on each shard that sends the message to its own clients, so a broadcast that reaches the siblings, like a **send** from the command line, calls it once per shard.

#### `on_route(method, path, backend_path)`

Chooses the backend for a request by returning its index (0-based). It is called by a proxy only, and only with **--strategy lua**. It answers only "where does this go". To accept or refuse a request before any backend is chosen, see **Proxy Filter Chain**.

The strategy decides whether the callback is consulted. A proxy created without **--strategy lua** keeps round-robin (or **random**, if that was requested) and never looks the callback up. A script that defines **on_route** on such a proxy loads without any report, and the proxy routes exactly as if the function were not there. That is the usual reason why an **on_route** that was tested and works appears to do nothing.

*path* is the path *as the client sent it,* including this proxy's own **/***name***/** prefix. *backend_path* is the same path with that prefix removed, which is what the backend will actually receive. A proxy named **gw** that is handed **/gw/api/users** sees both:

```
function on_route(method, path, backend_path)
    -- path         == "/gw/api/users"
    -- backend_path == "/api/users"
    if backend_path:match("^/api/") then return 0 end
    return 1
end
```

Both are offered because each is the truth about a different thing. The filter chain judges the request the client made, so it is handed *path*. A routing decision is usually about the endpoint being addressed, which is *backend_path*.

*backend_path* exists so that scripts stop computing it. Doing it by hand means stripping **"/" .. self.name .. "/"** and getting the bare case right, and the bare case is the one nobody gets right. The gateway's own root arrives as **/gw**, three characters against a five-character prefix, and must become **/**. A **sub()** past the end yields the empty string, which matches no pattern at all.

The arguments are passed with **--protocol http** only. A TCP proxy has no request line to read them from, and calls **on_route** with none. So a body written for HTTP, such as `**return hash(path) % n**`, raises on the first request when it is moved to a TCP proxy.

A handler that declares only two parameters is unaffected. Lua discards arguments that a function does not name, so every **on_route** written before this existed behaves exactly as it did.

If a call raises, or returns anything other than an index inside the backend list, it selects nothing. The proxy reports the error on stderr and falls back to the selection it would have made without the callback. The request is forwarded either way. Refusing a request is the filter chain's job, not this callback's.

#### `filters`

Not a callback but an array of them, for a proxy only: see **Proxy Filter Chain**.

#### `routes`

Not a callback either, but a table in which this runtime declares what it answers. The daemon publishes it to the proxies in front of the runtime: see **Declared Routes**.

#### `on_proxy_request(client_id, data) -> string | nil`

Called for every chunk forwarded from a client to a backend (proxy only). Return a modified string to replace the data, or **nil** to drop the chunk entirely, so that the backend never receives it.

Returning nothing at all forwards the chunk unchanged, which is not the same as returning **nil**. A hook written to watch traffic (**function on_proxy_request(id, data) log(data) end**) ends without a return. If that were read as **nil**, the most natural three lines in this API would discard every byte through the proxy. The filter chain draws the same distinction: a filter that returns nothing has no opinion, and the chain continues.

The hook fails closed, like the filter chain and for the same reason. If it raises a Lua error, or returns anything other than a string or **nil**, the request is refused. The connection to the client and the one to the backend are both closed, and the reason is logged. The hook is where a script strips a header or rejects a request. Forwarding the unmodified bytes when it could not run would admit exactly what it was there to refuse. And **return false** is a rejection, not a value to guess at.

The refusal closes the connections rather than answering with a status. This callback is on the byte path: it is called with body chunks as well as with the request head, and it carries TCP as readily as HTTP. To refuse a request with a status line, use the filter chain; see **Proxy Filter Chain**.

#### `on_proxy_response(client_id, data) -> string | nil`

Called for every chunk forwarded from a backend to a client (proxy only). It works like **on_proxy_request**. Returning nothing forwards the chunk unchanged, a replacement string replaces it, and nil drops it. An error, or a return of any other type, refuses. Here the refusal closes the client connection, because the response this hook was to redact must not be delivered unredacted.

#### `on_master_auth(client_id, password) -> bool`

Decides whether a client gets the master role, on a server in master mode. Return **true** to grant the master role. If this callback is defined, it overrides **--master-pw**, so it is the entire gate on that server.

Its result is read strictly, and it fails closed: only the boolean **true** grants. Anything else denies: **false**, **nil**, no return at all, and every truthy non-boolean, such as a string, the number 0 or a table. If the callback raises a Lua error, the attempt is denied and the error is logged. A denial from this callback is counted against the source address exactly as a wrong **--master-pw** is, so the per-address lockout described there applies here too.

#### `on_auth(client_id) -> bool`

Decides whether to admit a client, right after it is accepted (server only). It is called before **on_connect** fires. Return **true** to admit the client, or **false** to reject it and close the connection. If the callback raises a Lua error, the client is also rejected (fail-closed). When no **on_auth** callback is defined, all clients are admitted.

#### `on_websocket(client_id, headers)`

Called right after a WebSocket upgrade handshake completes (server only). By then, **on_connect** has already fired. The *headers* argument is a Lua table with any subset of these keys from the HTTP upgrade request: **cookie**, **origin**, **protocol** (Sec-WebSocket-Protocol) and **authorization**. Only keys present in the request are set; absent headers are nil. This callback never fires for plain TCP clients.

#### `on_http_request(req) -> table`

Called when the server receives an HTTP request (server only). The server detects HTTP from the first bytes; see **Multi-Protocol Auto-Detection**. The *req* argument is a table with these fields:

```
method      string   HTTP method ("GET", "POST", etc.)
path        string   Request path (e.g. "/api/users")
query       string   Query string without leading ? (empty if none)
body        string   Request body (empty for GET)
client_id   number   File descriptor of the client
version     string   HTTP version (e.g. "1.1")
headers     table    Request headers {["Host"]="...", ...}
```

Header names arrive as the client spelled them. Values arrive with optional whitespace (spaces and tabs) removed from both ends, so **X-Token: abc** reaches the callback as **abc**. A request whose framing this server refuses never reaches the callback. See **Request Framing** above for those requests and how they are answered.

Return a table with the HTTP response:

```
{
    status  = 200,                              -- HTTP status code
    headers = {["Content-Type"] = "text/html"}, -- response headers
    body    = "<h1>Hello</h1>"                  -- response body
}
```

If no **on_http_request** callback is defined, the server falls back to static file serving (**--http**) or returns 404. Returning nothing, or anything that is not a table, has the same effect: the request falls through to the static file or the 404. Only **nil** and no return at all do this silently; they are how a handler declines. Any other value means the script meant to answer, so the daemon's log names the fall-through as **[lua <runtime>] on_http_request returned a string; expected a table or nil ...**.

In the returned table, **status** must be a number, **body** a string, and **headers** a table of string to string. A field the script did not set takes its default: 200, an empty body, and no headers. A **status** or **body** that is present but of the wrong type makes a response this server cannot build. The request is then answered **500 Internal Server Error**, and the field and the type it arrived as are written to the daemon's log. A header whose name or value is not a string costs the client only that one header, not the whole answer, and is logged the same way.

HTTP/1.1 keep-alive is supported: the connection is reused for later requests unless the client's **Connection** header asks to close. That request is honoured for a Lua response exactly as it is for a static file.

A callback that **raises** is not a callback that declined. The request is answered **500 Internal Server Error**, and the error is written to the daemon's log as **[lua <runtime>] on_http_request error: ...**. Falling through to the 404 would make a broken handler look the same, to the client, as one that had no answer.

Example:

```
function on_http_request(req)
    if req.method == "GET" and req.path == "/health" then
        return {status = 200, body = "ok"}
    end
    return {
        status  = 200,
        headers = {["Content-Type"] = "application/json"},
        body    = '{"method": "' .. req.method .. '", "path": "' .. req.path .. '"}'
    }
end
```

#### `on_tick(dt)`

Called at a configurable interval while the runtime is running. *dt* is the actual time elapsed since the last tick, in milliseconds (a double). The interval is set by a top-level **tick_ms** global in the Lua script: a whole number of milliseconds, 10 or more. Default: 100, when the global is omitted. A value below 10, or one that is not a whole number, makes the script refuse to load, with a reason; it is not rounded into something else. 10 is the shortest interval **on_tick** can be armed at, and the daemon will not do what a script asking for less requests. Example:

```
tick_ms = 50
function on_tick(dt)
    self.broadcast("ping")
end
```

#### `on_miss(key) -> value [, ttl_seconds]`

Called when **GET** finds nothing (cache only), so the script can fetch the value from somewhere else. What it returns is stored and answered as a hit. See **Database Backend** for the four cache callbacks in full, with their ordering and their failure behaviour.

#### `on_write(key, value, ttl)`

Called after a successful **SET**/**SETEX**/**SETNX**/**MSET** (cache only).

#### `on_delete(key)`

Called after a **DEL** that removed something (cache only).

#### `on_expire(key)`

Called after the TTL sweep removes a key (cache only).

#### `on_upstream(conn_id, data)`

Called for each newline-delimited message received from an upstream connection (server only). Use -u to configure upstreams.

#### `on_upstream_connect(conn_id)`

Called when an upstream connects, including automatic reconnects (server only).

#### `on_upstream_disconnect(conn_id)`

Called when an upstream disconnects (server only).

#### `on_cluster_join(daemon)`

Called when a new remote daemon is discovered (cluster only). See **Cluster Event Callbacks**.

#### `on_cluster_leave(daemon)`

Called when a remote daemon becomes stale or disappears (cluster only).

#### `on_group_change(group, members)`

Called when the member count of a group changes (cluster only).

## Callback Deadline

Every invocation of a Lua callback has a wall-clock time budget. Default: **10000** milliseconds. When a callback is still running at the end of its budget, the runtime stops it with an error, exactly as if the script had called **error()**. The daemon logs the reason, the callback's usual failure path runs, and the runtime goes on serving.

The bound exists because a process serves its runtimes on one event loop, on one thread. Without it, **while true do end** in any callback would freeze that process for good. In a worker it would stop that runtime; in the daemon it would also stop the metrics endpoint and the IPC socket. Only **kill -9** would end it.

The budget applies to:

- each invocation of any **on_*** callback, separately. A periodic **on_tick** gets a fresh budget on every tick.
- each invocation of a **socketley.set_timeout** or **socketley.set_interval** callback, and of a **socketley.subscribe** handler.
- the whole **filters** chain for one request. The chain shares one budget; each filter does not get its own.
- the script's top level, which runs inside **create**. If the top level never returns, the create is refused with a reason, so the command does not hang the terminal.

**How it is enforced.** Nothing inside the callback times it. A worker writes each invocation into a line of memory it shares with the daemon, three stores with no clock read and no system call. The daemon reads every worker's line every 100 milliseconds. An invocation it finds running on two reads in a row, and past its budget, is sent **SIGURG**. The worker's handler puts an instruction hook on the interpreter, the hook raises the error at the callback's next VM instruction, and it comes off again when the callback ends. The budget is measured from the start of the event-loop turn the callback runs in, so a callback is stopped between its budget and about a tenth of a second after it.

LuaJIT's trace compiler is on for every callback, whatever the budget. A loop the compiler has turned into a trace never goes back to the interpreter, so it never reaches the hook. When a stopped callback is still running after its grace, one second or a quarter of its budget, whichever is longer, the daemon kills its worker, and the runtime's usual restart replaces it. The daemon logs **runtime 'NAME': on_message did not stop at its 500ms deadline; its worker is replaced** and **ls** counts the restart. A replaced worker loses what it held: its connections, and a cache's keyspace unless it is persistent.

The script's top level runs before the compiler is opened. A top level that never returns is therefore always stopped by the hook, and its create refused, rather than answered by replacing a worker that is still starting.

A process the daemon does not watch arms a one-shot timer for each callback instead, with the same signal and the same hook: the daemon running its own configuration file, and a runtime that an SDK program runs inside its own process. That costs two system calls a callback, and there a script with a budget runs with the compiler closed, because nothing outside that process could end a compiled runaway.

The budget counts time spent running on the loop, not elapsed clock time. This matters for the callbacks that can wait, such as **on_message**, **on_client_message** and an **mcp** tool's handler (see **socketley.http**). They run on a coroutine. A handler that is waiting in **self.cache** does not hold the thread and does not use up its budget. Each stretch in which it actually runs gets the budget. How long it may stay suspended is a separate bound of ten seconds, with its own result. See **self.cache** under **Runtime Methods**.

A callback stopped at its deadline is treated as a callback that raised an error. Wherever a raised error already has a defined result, the deadline gives the same result:

- **on_auth** denies the request and says why.
- **on_route** falls back to the usual backend selection.
- A **filters** entry refuses the request with a 500.
- In **on_proxy_request** and **on_proxy_response**, a timeout counts as a refusal, not as "returned nothing". The connection closes. The proxy does not forward the bytes of a request whose hook never finished deciding, as if the hook had let them through.

**socketley.http** runs inside the same budget. Its **timeout_ms** is clamped to the time left in the callback's budget. A callback that spends its budget waiting on a host therefore gets an ordinary **ok = false** result instead of being stopped. A script that needs a long fetch raises its callback budget to fit. A stop that arrives during the request does not cut it short: the wait goes on to its clamped end, and the error is raised at the callback's next VM instruction.

**Setting it.** A script sets its own budget with a top-level **callback_timeout_ms** global, next to **tick_ms**:

```
callback_timeout_ms = 30000   -- this script does slow work on purpose
callback_timeout_ms = 0       -- no bound at all for this script
```

An operator changes the default for every script that does not set its own with **SOCKETLEY_LUA_TIMEOUT_MS** in the daemon's environment; see **ENVIRONMENT**.

**What it costs.** A callback with a budget costs its worker three stores into the line on the way in and one on the way out, with no clock read and no system call. Measured with one build, the default budget against **0**, interleaved, seven passes each, in messages a second:

```
                               default           0   default/0, per pass
client firehose, 64 B       39,921,955  40,370,413   0.981 [0.966 .. 1.014]
client send, 64 B           26,076,696  25,958,758   1.015 [0.994 .. 1.036]
server Lua echo, pipelined   3,835,606   3,883,802   0.989 [0.979 .. 1.018]
server, arithmetic+strings     292,037     289,750   1.008 [0.998 .. 1.023]
```

Every range takes in 1. Against the count hook this replaced, which also kept the compiler closed, the default budget serves 1.08 times as much on the firehose (37,018,042), 1.04 times on the send (25,206,565), the same on the echo (3,857,682), and 1.57 times on the callback that computes (186,155).

The daemon's sweep wakes it ten times a second while any worker runs: an idle daemon with one idle runtime spent 9.4 milliseconds of CPU in 30 seconds, against 2.2 before.

**What the compiler gives.** Before the deadline was watched from outside, a callback with a budget ran interpreted, and setting the budget to **0** was the only way to open the compiler. These measurements compare the two arms, and every callback now runs in the compiled one. On an arithmetic callback the interpreted run served 11722 messages a second and the compiled run 28085, at 85.2 and 30.3 microseconds of worker CPU per message.

A callback that only answers a message gains very little, because there is almost no loop to compile. On the echo fixture the two arms do not differ in throughput: 42850 and 43929 messages a second interpreted, against 43577 and 44350 compiled. That gap is smaller than the spread inside either arm. What does differ is Lua's own share of the worker's CPU: 5.2 and 5.1% interpreted, against 3.9 and 4.0% compiled. That is the compiler doing a little work on two bytecodes. End to end this is about 1%, against 2.4x on a callback that computes.

A streaming producer falls between those two cases. It matters because it is the shape that runs per byte rather than per message. A handler that generates 40,000 CSV rows into **self.send_chunk** gains 25 to 48 per cent, not 2.4x. The profile shows why. With the hook installed, the interpreter takes 92.7 per cent of the worker's core. About 35 per cent of that is spent in **lj_str_new**, **lj_str_resize**, **gc_sweepstr** and the allocator. A compiled trace allocates and interns every string it builds exactly as the interpreter does. The compiler removes the dispatch cost but leaves the string cost in place.

So the way the script builds its strings is the larger lever, and the two effects multiply rather than add. The table shows the same handler using **string.format** instead of a chain of **..** concatenations, at 8 concurrent requests and then at 64:

```
                      interpreted     compiled
.. concatenation        97.8/s      130.6/s   (+34%)
string.format           93.8/s      160.0/s   (+71%)
.. at 64 concurrent      68.0/s      100.8/s   (+48%)
string.format at 64     71.5/s      142.7/s  (+100%)
```

Both arms put byte-identical responses on the wire. The compiled column is the one that changes. In the interpreter, **string.format** gains nothing: it is 4 per cent behind concatenation, inside the spread, because there each row costs one C call either way. **string.format** pays off only when the compiler is on, and then it pays twice. It builds one string per row instead of a chain of intermediate strings, and it uses an integer formatter instead of the double formatter, which alone took 15.6 per cent of the core. Compare the default with concatenation against the compiler with **string.format**. End to end, the second gives 64 per cent more throughput at 8 streams and 110 per cent more at 64, for about half the CPU per request.

A C server that builds the same rows with **snprintf**(3) still serves 2.4x the best of those results. The choice is therefore about how much of a stream's work belongs in Lua at all. No setting closes that gap.

**What decides the size of the gain** is how much of the work happens at the Lua level, not how many bytes pass through. This was measured on a proxy, a second runtime type with a per-byte hook. Both handlers forward the bytes unchanged, so only the work differs:

```
                          interpreted    compiled   CPU per request
one C library call per chunk    120.9      121.9     8223 -> 8155 us
a Lua loop over every row       417.1     1452.0     2378 ->  669 us
```

The first handler runs one **gsub** over each chunk and gains one per cent. The call is C either way, and there is almost no Lua around it to compile. The second walks the rows in a Lua **while** loop and gains 248 per cent, with 72 per cent less CPU. Every runtime type reads this setting from the same place. The five shapes measured so far therefore rank by that one question, how much work is done in Lua:

- about one per cent for a C call per byte, or for a callback that only answers;
- 34 to 48 per cent for building strings, where the allocator and the intern table are the cost and the compiler cannot remove them;
- 2.4x for arithmetic;
- 248 per cent for Lua control flow over many items.

**How the reply is assembled decides both,** and the number of pieces decides whether it matters at all. The tables below compare four idioms that build one reply out of N parts. They ran on a server, with one binary and one C client, interleaved. In the N = 1000 table, each pair of rows is the same script with the compiler closed and then open:

```
  N = 24, compiler closed       exchanges/s   spread
    s = s .. piece                 160,495      22%
    s = s .. string.format(..)     153,658      24%
    t[i] = piece, concat once      159,721      23%
    t[i] = format, concat once     166,023      15%
```

This table shows no real difference: every spread is larger than every gap. Assemble a short reply in whatever way reads best. **string.format** is not faster here.

```
  N = 1000                      exchanges/s   us cpu/req   spread
    s = s .. piece                   1,251         801      6%
                  compiler open      1,426         703      6%
    s = s .. string.format(..)         923       1,087      8%
                  compiler open        843       1,192      5%
    t[i] = piece, concat once        7,618         131      6%
                  compiler open     13,361          75      2%
    t[i] = format, concat once       8,656         115      7%
                  compiler open     17,675          57      5%
```

At a thousand pieces, the best shape serves 14.1 times as many exchanges as the worst, at a fourteenth of the CPU per request. Joining once accounts for most of that: 6.1x on its own. The formatter adds a further 14 per cent on top of joining once. When the formatter is used to accumulate instead, it is 26 per cent *slower*. The same call has opposite effects, depending on the code around it.

The effect on the compiler is the part worth remembering. Opening the compiler gains 14 per cent on the accumulating shape and nothing outside the spread on the accumulating shape that formats. It gains 75 and 104 per cent on the two shapes that join once. This is the rule above seen from the other side. Accumulating moves the work out of Lua and into the allocator, where the compiler cannot reach it. A script that is slow because of its idiom does not become fast because of this setting.

**What 0 turns off.** Setting the budget to **0** arms nothing and writes nothing: the worker writes no line, the daemon sends no signal, and no callback of that script is ever stopped or its worker replaced. It no longer changes what is compiled.

**What a compiled runaway costs.** A compiled trace never calls the instruction hook. A runaway loop the compiler has made a trace of, such as **while true do n = n + 1 end**, is ended by replacing its worker at the end of its grace, not stopped in place. Measured with a 500 millisecond budget, the replacement was listening 1.71 seconds after the message that started the loop. A loop that raises and catches an error on each turn goes back to the interpreter, and it was stopped in the same worker after 0.52 seconds.

A runaway callback affects one runtime, not the whole daemon. In a measurement with a server whose callback never returns and no budget, that server's worker process sat at 83% of a core. Meanwhile a second server on the same daemon went on echoing, and the daemon went on answering **ps**. A runaway in the script's top level is always refused, whatever **callback_timeout_ms** says. The top level runs under the default budget, before the script's own setting has been read.

**What it does not bound.** A callback stopped at its deadline has still held the loop for that long. A CLI command issued during the stall can hit its own five second receive timeout and report the daemon unreachable; the command succeeds on retry. A runaway **on_tick** is stopped on every tick, not once. The budget is dated from the start of the loop turn, so the callbacks that ran before this one in the same turn count against it too. Time in a C function, such as an **os.execute** or an **io** read, is counted, but the stop is seen only when the callback is back in the VM; one that is still inside the C function at the end of its grace has its worker replaced. Name resolution inside **socketley.http** executes no VM instructions, so it is not interrupted. Instead, the call gives up on it at the call's deadline.

## Proxy Filter Chain

This applies to a proxy in HTTP mode only. **filters** is a global array of functions that the proxy runs in order on each request, *before* it selects a backend. Each filter either returns nothing, and the next filter runs, or returns a response, which ends the request there.

The order is the point. A request that a filter refuses never reaches backend selection. No endpoint is resolved, no circuit breaker's half-open probe is claimed, no pooled socket is used and no connection is opened. Authentication, rate limiting and header rewriting belong here. **on_route** runs after a backend has been chosen, and answers a different question.

The chain is independent of **--strategy**. It runs whatever selects the backend afterwards, and it also runs on a proxy with no **on_route** at all. A proxy whose script declares no **filters** array pays nothing for the chain: the chain is guarded by the same callback mask as every other hook.

Each filter is called with one argument:

```
method      string   HTTP method ("GET", "POST", ...)
path        string   Request path as the client sent it, this proxy's
                     prefix included — the same path on_route sees
version     string   HTTP version (e.g. "HTTP/1.1")
client_id   number   File descriptor of the client; pass it to
                     self.peer_ip() to identify the peer
headers     table    Request headers. Names are lowercased, values
                     are trimmed, and a field sent more than once is
                     joined with ", ".
```

And returns one of three things:

#### `nil`

The filter has no opinion (returning nothing means the same), and the next filter runs.

#### `{ status = N, body = string, headers = table }`

The response to send. The chain stops, the request is never forwarded, and this response goes to the client. *status* must be 200-599. *body* and *headers* are optional. The proxy closes the connection afterwards, as it does for every other response it writes itself.

#### `{ set_headers = table }`

Continue, with these headers set on the request that goes to the backend. A header set here replaces a client header of the same name instead of being joined to it. The proxy sends it with a lowercased name.

#### `{ remove_headers = { name, name, ... } }`

Continue, with these headers removed from the request before it goes to the backend. Every occurrence of each name is removed, so a field the client sent twice disappears entirely. Use it for a header the backend must never see, whatever the client sent: an internal trust header that a caller forged, or a cookie that has no business past the edge. *set_headers* and *remove_headers* may appear in the same table. When a name is both set and removed, the later of the two statements wins, in the same way that two *set_headers* for one name are resolved.

A filter that returns anything else, or that raises an error, refuses the request with 500. A filter that did not say "continue" is never treated as if it had. For the same reason, an entry in **filters** that is not a function makes the whole script fail to load: a silently dropped filter looks exactly like one that lets everybody in.

Some header names cannot be set *or removed* by a filter. The proxy drops them and writes a line to stderr:

- **Content-Length** and **Transfer-Encoding** on either side. The proxy forwards exactly the body that the parsed request declared. A filter that changed the length would make the proxy and the backend disagree about where the request ends.
- **Host** on the request, because the proxy rewrites it to the endpoint it selected.
- the hop-by-hop set (**Connection**, **Keep-Alive**, **TE**, **Trailer**, **Upgrade**, **Proxy-***).

The proxy also drops any name that is not a bare token and any value that contains CR or LF, because a filter often echoes something the client supplied.

Filters run on the event loop thread. Every request on the proxy waits for whatever a filter does, so a filter must not block, do synchronous I/O or run long loops.

Example:

```
filters = {
    function(req)
        if not req.headers["authorization"] then
            return {
                status  = 401,
                body    = "authentication required\n",
                headers = {["WWW-Authenticate"] = "Bearer"},
            }
        end
        return {set_headers = {["x-authenticated-user"] = "alice"}}
    end,
}
```

See **examples/proxy/filter-chain.lua** for authentication, per-IP rate limiting and header rewriting as three filters in one chain.

## Declared Routes

**routes** is a global array in which a runtime states what it answers: each entry is a path and the methods allowed on it. The array is declared in the *handler's* script. It is published to the proxies that forward to that runtime. Those proxies then refuse other methods at the edge, before any endpoint is resolved, any socket is taken from the pool or any connection is opened.

The declaration lives with the handler on purpose. A method list configured on the proxy would be a second copy of something the handler already states in its own code, in another runtime and soon in another process. Two copies drift apart. For example, the handler adds **PATCH**, the gateway goes on refusing it, and neither side alone explains the 405. Nothing is configured on the proxy. To change what the gateway enforces, edit the handler's script and run **socketley reload-lua**.

```
routes = {
    { path = "/endpoint/login", methods = {"POST", "GET"} },
    { path = "/static/*",       methods = {"GET"} },
}
```

**path** is the path as the *handler* sees it, with the proxy's own **/***name***/** prefix already stripped. A query string is not part of it. A trailing * makes the path a literal prefix; there is no other pattern syntax. An exact match wins over a prefix, and among prefixes the longest one wins. **methods** is a list of method names; a single method may be given as a bare string. The proxy uppercases the declared methods when the script loads, so **methods = {"post"}** declares POST. The method a client sends is compared exactly as sent. RFC 9110 9.1 makes the method token case-sensitive, and the handler would also refuse a request for **post**.

What the proxy does with the declaration:

#### `A declared method`

is forwarded, as always.

#### `An undeclared method on a declared path`

is answered with **405 Method Not Allowed** and an **Allow** header that lists the methods that would have worked. No backend is involved.

#### `HEAD`

is allowed wherever **GET** is (RFC 9110 9.3.2). A handler that serves GET serves HEAD, whether or not it listed HEAD.

#### `OPTIONS`

is never refused. A plain OPTIONS request ("what may I do here", RFC 9110 9.3.7) is answered with **204** and an **Allow** header built from the declaration. A CORS *preflight* (an OPTIONS carrying **Origin** and **Access-Control-Request-Method**) is always forwarded to the handler instead. The declaration says nothing about origins, and an answer without **Access-Control-Allow-Origin** breaks the preflight just as a 405 would: the browser never sends the real request and reports a CORS error. A handler that declares **OPTIONS** itself always receives it.

#### `A path nobody declared`

is forwarded, whatever the method. A declaration covers only the paths it names and says nothing about the others. It is not a whitelist: declaring one route does not hide the rest.

#### `A backend given as host:port`

has no declaration and can never have one, because the published snapshot is keyed by runtime name and by group. The proxy forwards to such a backend as before.

For a proxy with several backends, or with an **@***group* backend, the declarations are merged under one rule: the proxy may not refuse anything that *either* possible target might have served.

- A path that only some of the targets declare is dropped, because a runtime that never mentioned it may well serve it.
- A path that all of the targets declare keeps the *union* of their methods, because the proxy does not know which target a request will reach.

So if one backend or group member declares nothing, that proxy enforces nothing at all. This is silent and deliberate: that target has said nothing about what it answers, so nothing can be refused on its behalf.

**Edge rejection is not input validation.** The proxy can confirm that the method is one the handler declared. It cannot confirm that the body is a well-formed login. The proxy is also not the only way in: a socketley server listens on its own port, and a request that arrives there passed no edge at all. A handler that stops checking its input because "the gateway checks" is safe only while every request comes through the gateway. That is a property of the deployment, not of the code. Declare routes to save the round trip and to state your intent, and keep validating input.

**socketley stats** *proxy* reports **declared_routes**, the number of routes that proxy actually enforces. Check it first when a method that should be refused is not. From the client side, all of these look the same, and all of them show 0 here:

- a backend that declares nothing;
- a backend named by address;
- a script that failed to load;
- a proxy whose handler had not started yet.

A malformed entry makes the script fail to load, with the reason on stderr; the entry is not silently dropped. A declaration that differs from the one in the file would be invisible from both sides. A **routes** table with no entry at index 1 is refused too. It must be an array, and **routes = {["/a"] = {"GET"}}** would otherwise load and declare nothing.

Neither end has to run in the daemon. A proxy in its own worker process enforces declarations the same way: the table reaches it in the endpoint frame that already carries the addresses. A *handler* in a worker also declares routes the same way, which is less obvious. The declaration is produced by running the script, and only the worker runs it. So the worker sends it back to the daemon in a **routes** frame on the control socket, and the placeholder publishes the worker's copy. Where either runtime runs makes no difference to which methods are refused.

See **examples/proxy/declared-routes.lua** for a handler that declares an AJAX endpoint and the gateway in front of it.

**Why exists and hexists are there.** **self.get** returns the value, and returns the empty string both for an absent key and for a key that holds an empty string. A script cannot tell the two apart from **self.get** alone, and this page's own example relies on that: *examples/cache/cache-integration-handler.lua* reads **self.get("config:timeout") == ""** as "not set yet".

Making **get** return **nil** for an absent key would answer the question, but it would break every script that reads the result that way. An empty string is also a value a cache may legitimately hold. So **exists** and **hexists** ask the question separately, under the names the wire protocol already uses.

**The proxy table is smaller than the server's on purpose.** A proxy relays between a client and a backend and speaks for neither. It has no message of its own to put on the wire, so it has no **broadcast()**, no **send()** and no per-connection metadata. To change what crosses a proxy, use **on_proxy_request** and **on_proxy_response**. To refuse a request, use the filter chain.

**self.backends()** is indexed from 1, like every Lua array, but **on_route** returns an index from 0. So when **on_route** returns **n**, the selected address is **self.backends()[n + 1]**.

**self.owner_send()** accepts only a client_id that this runtime was actually given: one that arrived through **self.route()** and was reported by **on_connect()**. It returns **false** for any other id, including a client_id whose connection has since closed. A script that holds an id after its connection has ended therefore cannot write to whichever client later received that descriptor.

## Global Functions

#### `socketley.log(msg)`

Writes one line to the daemon's log at **INFO** level, prefixed with the name of the runtime that wrote it: **[12:04:31] [INFO] [lua my-server] ...**. The line goes through the daemon's logger, so **log_level** in the configuration file can suppress it like any other message. At the default level, every line is shown. Every Lua diagnostic carries the same **[lua <runtime>]** prefix. The prefix is what separates two scripts that share one stderr. Two runtimes often share one script file, so the file name in an error does not identify the runtime.

#### `socketley.set_timeout(ms, fn) -> timer_id`

Calls *fn* once after *ms* milliseconds, using an io_uring timeout SQE. Returns an integer timer ID that can be passed to **socketley.clear_timeout()**. The timer shares the event loop with the runtime and uses no extra threads.

#### `socketley.set_interval(ms, fn) -> timer_id`

Calls *fn* every *ms* milliseconds. Returns an integer timer ID that can be passed to **socketley.clear_interval()**.

Both kinds of timer are cancelled when the runtime stops, and are **not** restored if it is started again. A stopped runtime executes no script, so its timers do not survive the stop. This includes a timer armed inside **on_stop**, which is cancelled with the rest. The script registers its timers at its top level, which runs once, when the runtime's worker is forked. A **start** after a **stop** forks a new worker, which runs the top level again and so arms the timers again. Nothing the previous worker held is carried over: the timer is not restored, but re-armed by a script that runs from the beginning.

Both functions return **0** and arm nothing when *ms* is not greater than zero, when the runtime has no event loop, or when the runtime has been stopped. The last case covers a script that calls **socketley.stop** on its own runtime and carries on. Since **stop** returns to the script, everything after that line runs on a runtime that is already down. A **start** lifts the stopped state before **on_start**, so a restarted runtime arms its timers exactly as it did the first time. **socketley.subscribe** returns 0 in the same situation, for the same reason. Real ids start at 1, so **0** is unambiguous. The reason is written to the daemon's log, because a timer that will never fire would otherwise fail silently.

#### `socketley.clear_timeout(timer_id)`

Cancels a pending timeout, so the timer does not fire. Calling it with an already-expired or invalid ID is safe and does nothing.

#### `socketley.clear_interval(timer_id)`

Cancels a repeating interval, so the timer does not fire again. Calling it with an already-expired or invalid ID is safe and does nothing.

Both functions remove the timer completely rather than just silencing it. The io_uring timeout is removed, the timer's storage is released, and the reference to the callback is dropped. The closure and everything it captured can then be garbage collected at once, not when the timer would have expired.

Both are safe to call from inside the timer's own callback. That is how to write a repeating timer that fires only once.

#### `socketley.json_encode(value) -> string | false, why`

Encodes a Lua value (table, string, number, boolean, nil) as a JSON string. Tables with consecutive integer keys starting at 1 are encoded as JSON arrays; all other tables as objects.

Object keys are written in sorted order, so encoding equal data twice gives the same string. A Lua table has no order of its own: a table filled with *alpha*, *beta*, *gamma*, *delta* may iterate as *beta*, *gamma*, *delta*, *alpha*. Without sorting, two tables holding the same data could encode differently. Anything that compares encoded documents depends on this: an ETag, a cache key, a signature, a deduplication hash, or a diff of two logged payloads.

Returns **false** and a reason when the value cannot be written as a document: a table that contains itself (directly or through any chain of fields), or a table nested deeper than 128 levels. A table reachable twice by different paths is not a cycle and encodes normally.

A string is truthy and **false** is not. So code such as **local s = socketley.json_encode(t)** needs no change, and **if not s then** tests for the refusal.

#### `socketley.json_decode(str) -> value | false, why`

Decodes a JSON string into a Lua value. Objects become tables with string keys, arrays become tables with integer keys (1-based). Null becomes nil.

Returns **false** and a reason for a document nested deeper than 128 levels, for bytes that are not a complete JSON document, and for trailing data after the document ends.

Refusing malformed input is what makes the return value trustworthy. Without it, a handler could not tell a truncated body from a complete one. For example, **[1,2** (a request body cut short by a dropped connection) would decode to an ordinary two-element table, and **{"a":}** to an empty table. **nul**, **garbage** and an empty string would all decode to nil, the same result as a document that really is **null**.

The depth limit is not a formatting preference. This call is meant for data from the network, such as a request body or a message payload, so whoever sent the data chooses its nesting depth, and the decoder recurses to follow it. Without the limit, a few hundred kilobytes of **[[[[** took the whole daemon down. No callback deadline covers this case: deadlines measure Lua execution, and this recursion is native code.

#### `socketley.subscribe(cache_name, channel, fn) -> subscription_id`

Registers *fn(channel, message)* to be called whenever the named cache runtime publishes to *channel*. The function is called on the subscribing runtime's event loop turn, not from the cache itself. When several subscriptions exist for the same channel, all of them fire, in registration order.

Returns an integer id for **socketley.unsubscribe()**. Ids start at 1 and are never reused, so **0** means the call was refused. The runtime has been stopped, and this registration would have outlived the stop that ended the others. See **socketley.set_interval** for the details: both calls refuse in the same cases, and a **start** lifts the refusal for both.

Messages are delivered only to a **running** runtime. Every registration a runtime holds is ended when it stops. A runtime that has never been started receives nothing either. Its top level has run, so the registration exists, but a runtime that is not running executes no script. The same rule cancels the timers. Both come back when the runtime is started again in a worker: a **start** forks a new worker, which runs the top level and **on_start** again (see **socketley.set_interval**). A server, client, proxy, cache, storage or dns runtime made by **socketley.create** runs in the daemon instead. There a **start** runs **on_start** but not the top level, so a subscription made in **on_start** comes back and a timer armed at the top level does not.

#### `socketley.unsubscribe(subscription_id) -> bool`

Ends one subscription. Returns **true** when it removed a live one, and **false** when the id names none (never issued, or already unsubscribed).

The id names one registration, not a channel, so two handlers on the same channel can be ended independently. It is safe to call from inside a subscriber's own callback; that is how to write a subscriber that runs only once. The removal takes effect from the next message, not in the middle of delivering the current one.

Unsubscribing explicitly matters while the runtime is up. **stop** ends all subscriptions, and **remove** and **reload-lua** destroy the context they live in. But none of those happens to a runtime that is simply serving. A script that subscribes from a callback that runs more than once, such as **on_tick**, registers the same handler again on every call unless it unsubscribes. Each publish is then delivered to every copy.

#### `socketley.mqtt.publish(runtime, topic, payload [, {qos=, retain=}] [, fn]) -> true | nil, why`

Publishes a message on an mqtt runtime of this daemon, as if the broker itself had published it. Returns true once the broker has the message. See **From the other runtimes** under **MQTT FLAGS**.

#### `socketley.mail.send(runtime, {to=, cc=, bcc=, from=, reply_to=, subject=, text=, html=, headers=, attachments=, raw=} [, fn]) -> id | nil, why`

Has a mail runtime of this daemon write a message and queue it. Returns the message's queue id once it is in the spool. **to**, **cc** and **bcc** each take one address or a list of addresses. Each attachment is a table **{name=,type=,data=}**. See **MAIL FLAGS**.

#### `socketley.http(opts) -> table`

Makes an HTTP or HTTPS request and returns the response. In a callback that can wait, the callback suspends at the call, and the runtime serves everything else until the answer arrives. The callbacks that can wait are the ones **socketley.db** may be called from without a function, and an **mcp** tool's handler. Anywhere else (**on_start**, **on_stop**, a timer, **on_http_request**, a filter, an **mcp** resource or prompt), the call blocks the event loop thread until the exchange ends. In those places, use it only in **on_start**/**on_stop** or in low-frequency **on_tick** callbacks.

*opts* table keys:

```
url         string   Request URL (http:// or https://)
method      string   HTTP method (default "GET")
body        string   Request body (optional)
headers     table    Extra headers e.g. {["Content-Type"]="application/json"}
timeout_ms  number   Timeout in milliseconds, 1..3600000 (default 5000)
```

A key that is present but has the wrong type or is out of range makes the call return **ok = false** with the reason in **error**. The key is not replaced by its default, so `timeout_ms = "soon"` does not silently become 5000. A key that is absent keeps its default; that is not an error and is not reported.

Returns a table:

```
ok      bool    true if HTTP status 2xx
status  number  HTTP status code (e.g. 200, 404)
body    string  Response body
error   string  Error message on failure
```

*timeout_ms* is one deadline for the whole exchange, not a separate timeout per operation. Connecting, the TLS handshake, the request and the response are all measured against it. A call that blocks resolves the host name before the deadline is armed, on a thread of its own, with the resolution bounded by the same timeout. A call that waits counts the resolution against the deadline. A response larger than 8 MB is refused rather than buffered without limit.

A response that declares a **Content-Length** and then ends before reaching it is also refused, with the shortfall named in **error**. Nothing else in the answer would show the problem. The close that cut the response short looks the same as the close that ends a response with no length at all. Over HTTPS, the **close_notify** alert would tell the two apart, but many servers omit it, and this client accepts its absence. Only a response with a declared length can fall short. A chunked response, or one with no length, is read until the close and returned as usual.

HTTPS uses OpenSSL and validates the peer. The certificate chain is verified against the system CA store, and the certificate must have been issued to the host in the URL. A host name is matched against the certificate's DNS names, with partial wildcards refused; an address literal is matched against its IP SAN. TLS 1.2 is the minimum accepted protocol version. If either check fails, the request is aborted with the reason in *error*. There is no option to disable the checks. A service that presents a self-signed or private-CA certificate must have that CA in the trust store OpenSSL reads (overridable with **SSL_CERT_FILE** or **SSL_CERT_DIR**). If no CA store is available at all the call fails immediately with **no system CA store available**.

## Runtime Management API

Create, start, stop, and remove runtimes from Lua scripts:

```
socketley.create(type, name, config)  -- Create runtime
socketley.start(name)                 -- Start runtime
socketley.stop(name)                  -- Stop runtime
socketley.remove(name)                -- Stop + remove runtime
socketley.send(name, msg)             -- Send/broadcast to runtime
socketley.list()                      -- List all runtime names (table)
socketley.get(name)                   -- Get info table or nil
socketley.pipe(src, fd_a, src, fd_b)  -- Pair two connections of one server
socketley.pipe(src, fd, dst)          -- Route a connection to another server
```

**Every call above answers true when it happened, or false , "reason" when it did not.**

The reason is a sentence that names the runtime and what was wrong with the request. A script can use it to tell these four situations apart:

```
local ok, why = socketley.start("web")
--  false  there is no runtime called "web"
--  false  "web" is already running
--  false  "web" is failed, and a failed runtime cannot be started again ...
--  false  "web" could not be started; it is failed now, and the reason is
--         in the daemon's log        <- a held port, a TLS pair that is not one
```

This is the convention Lua itself uses, in **io.open**, **os.remove** and **pcall**. So **assert(socketley.start(n))** prints the reason with no other change. Success returns ONE value, not **true, nil**.

**What a second return value changes.** Lua truncates a multiple-return call to one value everywhere except in three places. These are unaffected: assignment, **if not f() then**, **and**/**or**, concatenation, **tostring**, comparison, and any argument position that is not the last. These are affected:

- **print(f())** prints two values;
- **{ f() }** builds a two-element table;
- **g(f())** passes **g** two arguments instead of one.

**socketley.pipe** is two calls, and the number of arguments selects which one. With four arguments it pairs two connections of ONE server; both descriptors are named and both are used. With three arguments it hands the connection to another *runtime*, which decides what answers it. That form has no destination descriptor, so a fourth argument across two runtimes is refused rather than accepted and ignored.

**Config table keys:** **port**, **config** (or **lua**, a script path), **target**, **mode** (server only), **http** and **http_cache** (server only), **group**, **on_parent_stop** ("remove" or "stop"), and **start** (bool). **The table is validated, and a refusal leaves nothing behind.** Each of these returns **false** and a reason, which also goes to the log, and creates no runtime:

- a port outside 0..65535;
- a mode or policy that is not one of the listed values;
- a key that is not on this list;
- a script that will not load;
- a **start** that cannot bind.

Runtimes created from Lua have parent-child ownership. port=0 creates an internal-only server that receives only forwarded messages.

**Every call above works in a worker, which is where every runtime runs.**

These calls act on the runtime map, which lives in the daemon. A script that uses them therefore runs in a process that does not hold the map. All of the calls still work there, in two different ways:

**socketley.send**, **.list**, **.get** and the four **socketley.cluster** calls are answered from a *replica.* The daemon pushes the worker a copy of the map and a snapshot of the cluster view, and refreshes both when they change.

**socketley.create**, **.start**, **.stop** and **.remove** *change* the map, and changing a copy would be wrong. The worker sends these calls to the daemon instead, over a socket it holds for exactly this purpose, and waits for the answer. So **if socketley.create(...) then** tests what actually happened. The wait is what makes the result accurate, and it is bounded. A call that does not fork anything took 9.95, 10.20 and 10.52 microseconds over three runs of 20000. A call that forks waits at most five seconds. These calls are made in **on_start** or on a rare control message, never per request, which is why a wait is affordable. Compare **socketley.http()** in the same table, which blocks the same loop for a network round trip.

The answers are the daemon's own, word for word what the same call says in the daemon: **there is no runtime called "x" ,** **"x" is already running ,** **a runtime called "x" already exists**. By design, a script cannot tell from them which process it runs in.

**Calls that cross runtimes work there too.** **socketley.pipe** across two runtimes and **self.route()** both work in a worker and cross the process boundary, with no change to how either is called.

One refusal remains; read it carefully if you meet it. **socketley.create**, **.start**, **.stop** and **.remove** raise an error in a worker that was forked *without* the socket these calls travel on. This happens with an older daemon, or with a daemon that could not create the socket. The error message says so and tells you to restart the daemon. It is not a permanent refusal.

Across two runtimes, **socketley.pipe** does not hand a file descriptor over at all, so no **SCM_RIGHTS** passing through **shared/net/conn_transfer.h** is involved. Both calls use **route_client**()**,** which writes into the target's connection maps, runs the target's **on_connect**, and then keeps the socket where it is and relays the bytes through it. This needs a way to name another runtime's connection and reach it, not a way to move one. That is **shared/ipc/route_relay.h**.

Nothing changes for a script: the same call, the same return value, the same target name. The origin stays in the data path either way, because that is what routing is. A message from a routed client reaches the target's **on_client_message**, and the target's reply reaches the client through the origin.

The four-argument form, **socketley.pipe(src, fd_a, src, fd_b)**, pairs two connections of one server and crosses no process boundary. It must be called from that server's own script, because only that process holds its connections.

When a runtime that holds routed connections goes away (stopped, removed, crashed or killed), every runtime on the other end of those routes is told to release them, and the target's **on_disconnect** runs. The daemon does this, not the departing runtime, because a killed worker runs no teardown at all.

**unroute()**, **get_route()** and **owner_send()** read the runtime's own tables, in a worker as anywhere else.

Plan for where that error is raised, when one of those four calls raises it. At a script's top level it fails the load, and a worker whose script did not load does not serve: the **create** is refused with a reason and the runtime is left **failed**. Inside a callback, the error is caught and logged like any other callback error, and the runtime carries on. In **on_start**, that means the runtime is up and serving, but nothing **on_start** was meant to do has happened. **ls** shows it green and it accepts connections. So the command that started it exits 1 and names the callback and the reason. The runtime is left running either way; the exit code and the message tell the two cases apart.

Everything that does not use the runtime map works in a worker exactly as it does in the daemon: **socketley.log**, **.http**, **.json_encode**/**.json_decode**, the timers, **.subscribe**, the whole **self** table, and every connection and request callback. See **Out-of-process runtimes** under **LIMITATIONS** for the full account.

## Cluster Introspection API

When the daemon runs in cluster mode (**--cluster**), the **socketley.cluster** table provides read-only introspection into the full cluster topology. All functions return empty tables when not in cluster mode, so scripts work in both standalone and cluster setups without modification.

In a worker process the four functions are answered from a snapshot of the cluster view, which the daemon pushes before the frame that loads its script.

One exception remains, and it is in a worker only. A daemon that is in no cluster has no view to push. An empty table is also what a *successful* call returns for a daemon that is alone in a cluster. So when no view is installed, the four functions raise an error that names the function, instead of returning. If a daemon *joins* a cluster after a worker's script has loaded, that script keeps getting the error until it is reloaded.

#### `socketley.cluster.daemons() -> table`

Returns an array of daemon info tables. Each entry has:

```
name      string   Daemon name (from --name)
host      string   Advertised address, from gethostname(2), falling
                   back to the daemon name if that call fails
runtimes  number   Count of runtimes on this daemon
```

The local daemon is always the first entry. Remote daemons follow in discovery order.

#### `socketley.cluster.runtimes() -> table`

Returns a flat array of all runtimes across every daemon in the cluster:

```
daemon       string   Name of the daemon hosting this runtime
name         string   Runtime name
type         string   "server", "client", "proxy", or "cache"
port         number   Listen port (0 = internal-only)
group        string   Group tag (empty string if unset)
state        string   "created", "running", "stopped", or "failed"
connections  number   Current connection count
```

The type is the name of any runtime type the daemon knows, built in or registered, not only these four.

#### `socketley.cluster.group(name) -> table`

Returns running members of the named group that have a valid port. Each entry has:

```
daemon       string   Daemon name
host         string   Advertised address
port         number   Listen port
connections  number   Current connection count
```

Useful for building custom routing, health checks, or failover logic from Lua.

#### `socketley.cluster.stats() -> table`

Returns aggregate cluster statistics:

```
daemons   number   Total daemon count (local + remote)
runtimes  number   Total runtime count across all daemons
running   number   Count of runtimes in "running" state
groups    table    Maps group name (string) -> member count (number)
```

## Cluster Event Callbacks

These optional callbacks fire when the cluster topology changes. Events are detected during the 2-second scan/publish cycle, so callbacks may fire up to 2 seconds after the actual change. They fire only on a **running** runtime. A runtime that has been stopped or has never been started executes no script, and that includes cluster callbacks. If one event in a batch stops the runtime, the remaining events in that batch are not delivered to it. A daemon is considered stale and triggers **on_cluster_leave** after 10 seconds without a heartbeat update.

#### `on_cluster_join(daemon)`

Fired when a new remote daemon is discovered in the cluster directory. *daemon* is a table with **name** (string) and **host** (string) fields.

#### `on_cluster_leave(daemon)`

Fired when a remote daemon's heartbeat file becomes stale (>10s old) or is removed from the cluster directory. *daemon* is a table with a **name** (string) field.

#### `on_group_change(group, members)`

Fired when the total member count of a group changes (a runtime joins or leaves the group, or a daemon with group members appears/disappears). It fires only on actual count changes, not on every scan cycle. *group* is the group name (string). *members* is an array of tables, each with **daemon**, **host**, and **port** fields representing the current group membership.

Example — log topology changes and maintain a local routing table:

```
local backends = {}

function on_cluster_join(daemon)
    socketley.log("daemon joined: " .. daemon.name .. " at " .. daemon.host)
end

function on_cluster_leave(daemon)
    socketley.log("daemon left: " .. daemon.name)
end

function on_group_change(group, members)
    if group == "api" then
        backends = members   -- update routing table
        socketley.log("api group now has " .. #members .. " members")
    end
end

function on_start()
    -- Initial snapshot
    local stats = socketley.cluster.stats()
    socketley.log("cluster: " .. stats.daemons .. " daemons, "
                  .. stats.running .. " running runtimes")
end
```
