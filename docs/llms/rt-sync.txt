# sync runtime

One job that carries a directory to a storage, from it, or both ways

A **sync** runtime is one job that carries files between a directory and a [storage](rt-storage.txt). Each job has its own line in `socketley ls`, its own log lines and alert.

```
socketley create sync photos --dir /srv/photos --storage ui/photos \
    --credentials /etc/socketley/sync.creds --mode out -s
socketley create sync offsite --dir /srv/photos \
    --storage https://files.example.com/photos --credentials /etc/socketley/offsite.creds \
    --every 1h --exclude '*.tmp,.git/*' -s
```

## What it does

- **Where**: `--storage`: a storage runtime (`ui/photos`), a host and port, or a URL, bucket last.
- **Which way**: `--mode` `out`, `in` or `inout`. Several targets only with `out`.
- **When**: On every change the kernel reports, plus a full walk every `--every`.
- **What**: All of `--dir` but the `--exclude` patterns, under `--prefix` in the bucket.

## Works with

A [storage](rt-storage.txt) runtime or any S3. A sync opens no port.

## Flags

Every flag a sync runtime takes, by group.

**Sync**

| flag | value | what it does |
|---|---|---|
| `--dir` | path | Directory: The directory whose files are carried. Required. |
| `--storage` | list | Storage: Where they go: a runtime and a bucket, or a URL and one. Required. |
| `--mode` | one of out, in, inout | Direction: Direction: out to the storage, in from it, or inout for both. |
| `--credentials` | path | Credentials: A file holding access_key and secret_key. Required. |
| `--prefix` | text | Prefix: The key everything is written under, below the bucket. |
| `--every` | text | Walk every: How often the whole directory is rescanned; never to sync on changes only. |
| `--exclude` | list | Exclude: Patterns of paths, relative to the directory, that are not synced. |
| `--repositories` | path | Repositories: The file a storage writes for a user's own sync runtime, which pulls their git repositories. |

## Benchmarks

A ratio (×) is how many times better socketley did: more per second, or less time, memory or CPU; above 1× socketley is ahead. The range in brackets is the lowest and highest ratio across the passes.

How it was measured: the carriers themselves; the storage target is one socketley storage runtime on other cores; the carriers on two cores, the target storage runtime in a daemon of its own on four others. One socketley storage runtime on tmpfs is the target for all three, a fresh bucket a run, every run checked key for key and byte for byte. rclone 1.75.2 runs as its S3 docs advise (--transfers 8 --checkers 16 --fast-list --update --use-server-modtime), mc mirror with --overwrite --remove and eight workers. A socketley job walks once at start and then follows inotify, where the others walk both sides again; it checks a whole tree only when it starts, so the re-check row is a stop and a start, with one file deleted so its end can be seen.

### A change noticed while running

mc 2025-08-13, 3 passes, 2026-11-08, socketley c8301617.

| case | socketley | mc | socketley vs mc |
|---|---|---|---|
| a 64 KiB file written, until it is in the storage | 0.91 ms (0.00 cores) | 1.53 ms (0.02 cores) | 1.60× (1.58–1.76) |

How it was measured: the carriers themselves; the storage target is one socketley storage runtime on other cores; the carrier on two cores, the storage on four others. Each file is timed from its write until a HEAD of its key answers with its MD5, one write at a time. rclone has no watch mode; mc mirror --watch is the nearest tool.

### Both ways at once

rclone v1.75.2, 3 passes, 2026-11-08, socketley c8301617.

| case | socketley | rclone | socketley vs rclone |
|---|---|---|---|
| both ways: 500 files changed here and 500 in the storage | 12 K files/s (0.35 cores) | 2.3 K files/s (1.58 cores) | 5.12× (5.12–5.19) |

How it was measured: the carriers themselves; the storage target is one socketley storage runtime on other cores; the carrier on two cores, the storage on four others. A tree and a bucket in step, then 500 files rewritten here and 500 others replaced in the storage, then one run: socketley --mode inout against rclone bisync. mc mirror carries one way only.
