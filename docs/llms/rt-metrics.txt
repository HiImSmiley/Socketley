# metrics runtime

Time series for years, answered with PromQL over the Prometheus API, with alert rules and logs

A **metrics** runtime keeps years of what socketley and nearby machines measure. It answers PromQL over the Prometheus HTTP API, so Grafana reads it as a Prometheus.

```
socketley create metrics metrics -p 9090 --scrape /etc/socketley/targets -s
socketley metrics query 'rate(socketley_runtime_messages_total[5m])'
socketley metrics query_range 'up' --start -6h --step 5m
```

## What it does

- **Collects**: This daemon's series with no setup; `--scrape` targets; remote write with `--receive`.
- **Stores compactly**: One to three bytes a sample, with coarser tiers (`--downsample`) for long ranges.
- **Stays bounded**: `--keep` limits age, `--max-series` cardinality; `--durable` loses nothing in a crash.
- **Alerts**: `--rules` in Prometheus's format, sent by webhook, mail or events (`--notify`).
- **Logs**: `--logs` keeps the daemon's log lines and answers LogQL as Loki does.
- **Archives**: `--archive` copies old blocks to an S3 bucket.

## Works with

The dashboard draws its history from it. A [storage](rt-storage.txt) runtime can hold its archive.

## Benchmarks

A ratio (×) is how many times better socketley did: more per second, or less time, memory or CPU; above 1× socketley is ahead. The range in brackets is the lowest and highest ratio across the passes.

### Scraping 100,000 series a second

Prometheus 2.53.5, VictoriaMetrics 1.112, 7 passes, 2026-11-03, socketley 9f644c07.

| case | socketley | Prometheus | VictoriaMetrics | socketley vs Prometheus | socketley vs VictoriaMetrics |
|---|---|---|---|---|---|
| CPU per sample ingested | 0.28 µs (0.03 cores) | 0.74 µs (0.07 cores) | 1.02 µs (0.10 cores) | 2.69× (2.57–2.74) | 3.68× (3.58–3.85) |
| resident memory | 277 MB | 363 MB | 119 MB | 1.20× (1.04–1.96) | 0.43× (0.29–0.79) |
| range query, 5 min of every path | 210 ms | 669 ms | 118 ms | 3.17× (2.98–3.25) | 0.56× (0.53–1.21) |

How it was measured: 50 targets × 2000 series, scraped every 1 s by all three at once; all three at once on the same two cores, the targets on four others; each pass a 60 s window. 50 targets of 2,000 series whose values change every second, scraped every second by all three at the same time, data on tmpfs. socketley's CPU includes its daemon's process. The range query asks five minutes of every path's request rate by status code at a 15 s step, the order of the three rotated.

## The manual on metrics

A **metrics** runtime stores what socketley and the machines around it measure, for years. It answers queries in PromQL over the Prometheus HTTP API, so Grafana reads it as it reads a Prometheus.

This daemon's own series reach the runtime without being written out as text. At each tick, the runtime asks the daemon for what changed since the last tick. These are the same series that **/metrics** writes, with **job="socketley"** and **instance** set to the daemon's name. Other daemons and any Prometheus endpoint are scraped. The runtime's rules raise alerts, which the daemon's **daemon.alert_webhook**, **daemon.alert_mail** and **daemon.events** deliver. The dashboard draws its history from this runtime.

```
socketley create metrics metrics -p 9090 --scrape /etc/socketley/targets -s
socketley metrics query 'rate(socketley_runtime_messages_total[5m])'
```

Every sample is stamped with the time its tick was due. So the samples of a series lie one interval apart and take one to three bytes each. Every two hours of samples are cut into a block on disk, and two-hour blocks are merged into a day. Beside them, the runtime builds coarser tiers with a step of five minutes and of one hour. For each step, a tier keeps the minimum, maximum, sum, count and last value, and a counter's increase. A query over a long range reads the coarsest tier that still answers it exactly. So a dashboard that shows a year reads a year of hourly points rather than three million samples.

#### `-p, --port port`

The port of the API. Default: 9090. It listens on 127.0.0.1 unless **--bind** names another address, and only a runtime guarded by **--keys** or **--idp** may do that. From outside the machine, the API is reached through the entrance with **--domain**, like any HTTP runtime.

#### `--keys file`

A file of service keys, one name and secret per line, in the format a **db** runtime reads. The runtime reads the file again when it changes. A request carries a key as **Authorization: Bearer** *secret*, or as Basic auth with the name and the secret, which is what Grafana's data source sends.

#### `--idp idp`

Admits the sign-ins of that idp runtime: a browser's session cookie, or an access token as Bearer.

#### `--idp-audience clients`

The comma-separated clients, one of which an access token's audience must name.

#### `--local, --no-local`

Whether the runtime collects this daemon's own series. On by default.

#### `--scrape file`

A file of the targets to scrape, one per line:

```
# name url [every=<duration>] [timeout=<duration>] [bearer=<file>] [label=value ...]
jetson http://127.0.0.1:9101/metrics every=15s site=home
node   https://box.example.com/metrics bearer=/etc/socketley/node.token
```

Each sample from a target gets **job** set to the target's name, **instance** set to its host and port, and the target's own labels. Each target also writes **up**, **scrape_duration_seconds** and **scrape_samples_scraped**. The series a target stops writing end at once with Prometheus's staleness marker, and so do all its series when it does not answer. A changed file is read again at the next tick. If the file cannot be read, the targets stay as they were.

A daemon at home that is reached through a **tunnel** is scraped as a loopback TCP service of its agent, so nothing is opened on its router.

#### `--every duration`

How often the runtime collects this daemon's series and scrapes a target that has no every= of its own. Default: 10s; takes 1s to 1h.

#### `--keep duration`

How long raw samples are kept. Default: 30d.

#### `--downsample step:keep[,...]`

The coarser tiers, each a step and how long it is kept. Default: 5m:1y,1h:5y; **none** turns them off. The first step must divide two hours. Each later step must be a multiple of the one before it, and must divide a day.

#### `--max-series n`

The most series the runtime holds at once. Default: 200000. A new series past the limit is refused and counted in **socketley_metrics_series_refused_total**. So one target that sends a label per request cannot take the machine's memory.

#### `--durable`

Logs every sample as it arrives, so a crash loses none. Without it, a crash loses what the open chunks hold, and a stop loses nothing.

#### `--rules file`

A file of recording and alerting rules, laid over the built-in ones (the alerts that **DASHBOARD** lists):

```
every=10s
alert DiskSpaceLow warning for=1m summary="{{ $labels.path }}: {{ $value | humanizePercentage }} free"
    : socketley_disk_free_ratio < 0.15
alert JetsonGone critical for=2m : up{job="jetson"} == 0
record job:requests:rate5m : sum by (job) (rate(http_requests_total[5m]))
off TargetDown
```

Each rule is one line, continued by lines that begin with a space. Its expression comes after **:** . **alert** takes a name and a severity, and then **for=**. **keep=** sets how long the alert keeps firing once its condition is gone. **every=** sets its own interval. **inhibits=***rule*[,...] names the alerts it silences on the labels both have. **summary=**, **description=** and **runbook_url=** are annotations, and any other *label***=***value* is a label. Values and annotations take Prometheus's templates (**{{ $value }}**, **{{ $labels.name }}**, **humanize**, **humanize1024**, **humanizePercentage**, **humanizeDuration**, **printf**). **record** writes its result as a series of that name. A rule with the name of a built-in rule takes its place, and **off** *name* leaves a built-in rule out.

The file is read again when it changes. If it cannot be read, the rules stay as they were, and the log says so. An alert is pending while its condition has held for less than **for=**. After that it is firing, and a notice goes out. When it is resolved, a notice goes out too. Its state is kept in the runtime's directory. So a restart neither sends a notice for it again nor starts its **for=** over. The **ALERTS** and **ALERTS_FOR_STATE** series are written as Prometheus writes them.

#### `--notify where`

Where alert notices go: **webhook**, **mail** and **events**, comma-separated. These are the daemon's **daemon.alert_webhook**, **daemon.alert_mail** and **daemon.events**. Default: all three; **none** sends no notices.

#### `--receive`

Accepts Prometheus remote_write at **POST /api/v1/write**. Each request is a Snappy-compressed WriteRequest of up to 16 MiB. Its samples are stored as they come, and the refused ones are counted in **stats**. A Prometheus, a Grafana Agent or another metrics runtime behind a firewall can then send what it has, instead of being scraped.

#### `--logs, --no-logs`

Also keeps every line the daemon and its runtimes write, and answers queries for them with LogQL over Loki's API. Off by default.

The lines are collected with the series at each tick, into one file per day in **logs/** of the runtime's directory. Grafana's Loki data source reads the runtime as it reads a Loki. Each line is labelled **job="socketley"**, **instance** (the daemon), **level** (**debug**, **info**, **warn**, **error**) and **name**. **name** is the runtime the line is about: the one that wrote it, or the one that a daemon line names. A start never collects a line twice. **socketley_log_lines_total** counts the lines by **name** and **level**, for a rule such as **increase(socketley_log_lines_total{level="error"}[5m]) > 0**.

The supported LogQL is a selector with **=**, **!=**, **=~**, **!~**, and the line filters **|= "text"**, **!= "text"**, **|~ "regex"** and **!~ "regex"**, which match anywhere in the line. Over these, it supports **count_over_time**, **rate**, **bytes_over_time** and **bytes_rate**, with **sum**, **count**, **min**, **max**, **avg** by or without labels. A query without a selector is PromQL.

#### `--logs-keep duration`

How long log lines are kept, in whole days. Default: 14d.

#### `--archive url`

An S3 bucket, with an optional key prefix, that blocks on disk are copied to. A block is copied once it holds a day or more, or once it ended two days ago. The URL has the form **http[s]://***host***/***bucket*[/*prefix*] and may point at a storage runtime of this daemon or at any S3.

The copied blocks are listed in **archived** in the runtime's directory and are never copied again. A refused copy is tried again each minute, and logged once. The archive keeps what **--keep** and **--downsample** delete here. Blocks copied back into **blocks/** of a stopped runtime are read at its start. A piece that a later merge replaced is dropped, as it lies inside a bigger block. A block that retention removes while the archive refuses every copy is not copied.

#### `--archive-credentials file`

A file with the bucket's **access_key** and **secret_key**, and also **region** and **session_token** when the bucket takes them. Each is a *key* **=** *value* line, as a sync runtime's **--credentials** holds them. The file is read again at each copy.

**The API.** The runtime serves:

- **/api/v1/query**, **query_range**, **series**, **labels**, **label/***name***/values**, **metadata**, **targets**, **rules**, **alerts**, **status/buildinfo**, **status/runtimeinfo** and **query_exemplars**, by GET or a POSTed form, answered in Prometheus's envelope;
- **/-/healthy** and **/-/ready**;
- with **--logs**, **/loki/api/v1/query_range**, **query**, **labels** and **label/***name***/values**;
- **/metrics**, with the runtime's own figures.

A Grafana data source of type Prometheus is pointed at **https://***domain* or **http://127.0.0.1:***port*, with the key as Basic auth or a Bearer header. The PromQL is Prometheus's:

- selectors, ranges and **offset**;
- the arithmetic, comparison and set operators, with **on**, **ignoring**, **group_left** and **group_right**;
- the aggregations, with **by** and **without**;
- **rate**, **irate**, **increase**, **delta**, **deriv**, **predict_linear** and the **_over_time** functions;
- **histogram_quantile**, **label_replace**, **label_join**, **absent**, and the time and maths functions.

Not supported: subqueries, **@**, and native histograms.

**The CLI.**

```
socketley metrics <rt> query '<promql>' [--at <time>]
socketley metrics <rt> query_range '<promql>' [--start <time>] [--end <time>] [--step <duration>]
socketley metrics <rt> series '<selector>' | targets | rules | alerts [--recent] | stats   [--json]
socketley metrics <rt> logs ['<logql>'] [--since <duration>] [--limit <n>]
```

**socketley export** writes a metrics runtime's settings, as it does for any runtime. **socketley export --full** first has a running metrics runtime write out what its head holds, and hold its merges until the archive is written. So a restore brings back every sample up to that moment.

A time is **now**, **-1h**, unix seconds or RFC 3339. By default, a range ends now and starts an hour back. **--json** prints what the API answers.

A metrics runtime does not accept **--shards**: each series is written by one process, and one process holds up to **--max-series** series (200000 by default).
