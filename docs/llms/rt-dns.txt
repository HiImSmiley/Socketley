# dns runtime

Authoritative name server for its zones, over UDP and TCP, with DNSSEC and transfers

A **dns** runtime is an authoritative name server for the zones you give it, over UDP and TCP on one port. It answers nothing else and is never an open resolver.

```
socketley create dns ns --zone example.com --publish 203.0.113.7 -s   # writes a zone file to start from
dig @127.0.0.1 example.com SOA
socketley create dns ns2 --zone /etc/socketley/example.com.zone \
    --publish 203.0.113.7 --transfer 203.0.113.53 --notify 203.0.113.53 --dnssec -s
```

## Good to know first

|  |  |
|---|---|
| `--publish` | Your public address. Needed when no interface has one, as behind NAT. |
| `--proxy none` | Skips the entrance `create` makes, which asks Let's Encrypt for certificates. Use it for a lab with real names. |
| `--rrl 0` | Lifts the default of 100 answers a second per client network, for a load test from one host. |

## What it does

- **Zone files**: RFC 1035 format; an edited file is served within a second.
- **UDP and TCP**: On port 53 unless `-p`; large answers move to TCP.
- **Secondaries**: AXFR to `--transfer`, NOTIFY to `--notify`.
- **DNSSEC**: `--dnssec` signs zones; `socketley <name> dnssec` prints the DS record.
- **Runtimes' names**: Answers for the `--domain` names of your runtimes ([how](man-dns-flags.txt)).

## Works with

Its entrance is a [proxy](rt-proxy.txt). A [mail](rt-mail.txt) runtime publishes its records through it.

## Flags

Every flag a dns runtime takes, by group.

**Basics**

| flag | value | what it does |
|---|---|---|
| `-p` | int | Port: The port it listens on (a client: the port of its target). |
| `-s` |  | Start now: Start it as soon as it is made. |
| `-g` (--group) | text | Group: Puts it in a group; a proxy with --backend @group reaches every member. |

**Network**

| flag | value | what it does |
|---|---|---|
| `--bind` | text | Bind address: Bind the port to this address only, such as 127.0.0.1 when only a proxy on this machine should reach it. |
| `--shards` | int | Shards: Worker processes sharing the port: the way one runtime uses more than one core. |
| `--cpus` | text | CPUs: The CPUs its I/O may run on, as 0-3,6. |

**Output**

| flag | value | what it does |
|---|---|---|
| `--log` | path | State log: A file it appends each state change to. |

**DNS**

| flag | value | what it does |
|---|---|---|
| `--zone` | list | Zones: Zone names (a file is written) or zone files. Required. |
| `--publish` | list | Public addresses: The addresses runtimes' names are answered with. |
| `--proxy` | text | Entrance: The entrance proxy it creates; none for no entrance. |
| `--proxy-port` | int | Entrance port: The entrance's port; 443 also makes the redirect on 80. |
| `--transfer` | list | Transfer to: Addresses that may copy the zones (AXFR): secondaries. |
| `--notify` | list | Notify: Secondaries told of each change. |
| `--rrl` | int | Rate limit: Response rate limit: answers a second to one network; 0 turns it off. |
| `--dnssec` |  | DNSSEC: Signs its zones; the parent takes the DS that socketley <name> dnssec prints. |

## Benchmarks

A ratio (×) is how many times better socketley did: more per second, or less time, memory or CPU; above 1× socketley is ahead. The range in brackets is the lowest and highest ratio across the passes.

### Authoritative DNS, one zone of 10,000 names

NSD 4.14.0, Knot 3.5.3, 9 passes, 2026-11-07, socketley 608e28c6.

| case | socketley | NSD | Knot | socketley vs NSD | socketley vs Knot |
|---|---|---|---|---|---|
| A queries over UDP | 484 K q per core·s (1.00 cores) | 360 K q per core·s (0.90 cores) | 301 K q per core·s (0.92 cores) | 1.34× (1.30–1.43) | 1.61× (1.55–1.69) |
| A queries over TCP, 128 connections | 195 K q per core·s (0.99 cores) | 54 K q per core·s (0.97 cores) | 63 K q per core·s (0.99 cores) | 3.51× (3.25–3.77) | 3.02× (2.85–3.30) |

How it was measured: dnsperf 8 threads, 32 sockets, 8 s a run, zone of 10000 names; each server one worker on one core, dnsperf on 20 others. Queries answered per second of server CPU (rate ÷ cores), because no server saturates its core at a window of 500 outstanding queries, and with more NSD and Knot drop UDP from their default socket buffers and dnsperf waits out each loss. socketley runs with --rrl 0 --proxy none: its response rate limit, on by default, would throttle one client host, and NSD and Knot have none by default. 90% of queries find a name, 10% are NXDOMAIN.
