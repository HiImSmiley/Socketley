# cache runtime

In-memory store on the Redis protocol: strings, lists, sets, hashes, sorted sets, streams, pub/sub

A **cache** is an in-memory data store that speaks the Redis protocol, so `redis-cli` and Redis libraries work unchanged. `nc` works too, in plain text.

```
socketley create cache store -p 6379 -s
redis-cli -p 6379 SET greeting hello
redis-cli -p 6379 GET greeting

socketley create cache sessions -p 6380 --maxmemory 512M --eviction allkeys-lru \
    --persistent /var/lib/socketley/sessions.bin -s
socketley create cache copy -p 6381 --replicate 10.0.0.5:6380 -s
```

> Warning: A cache has no password. It serves this machine only, unless created with `--public` or mutual TLS (`--tls --cert --key --ca`).

## What it does

- **Redis data types**: Strings, lists, sets, hashes, sorted sets, streams; see [commands](man-cache-flags.txt).
- **Redis features**: TTLs, pub/sub and transactions over [RESP](man-cache-flags.txt).
- **Bounded memory**: `--maxmemory` with an `--eviction` policy.
- **Persistence**: `--persistent file`; `--persistent-interval` journals writes.
- **Replication**: `--replicate` makes a read-only [follower](man-cache-flags.txt).
- **Several cores**: `--shards N`, one keyspace; `--cluster` for cluster-aware clients.
- **Database backing**: Lua `on_miss` reads through, `on_write` writes behind; see [database backend](man-cache-flags.txt).

## Works with

A [server](rt-server.txt) with `--cache` lets its clients and scripts reach it.

## Flags

Every flag a cache runtime takes, by group.

**Basics**

| flag | value | what it does |
|---|---|---|
| `-p` | int | Port: The port it listens on (a client: the port of its target). |
| `-s` |  | Start now: Start it as soon as it is made. |
| `-g` (--group) | text | Group: Puts it in a group; a proxy with --backend @group reaches every member. |
| `--lua` | path | Lua script: A script with the runtime's callbacks, run at start. |

**Network**

| flag | value | what it does |
|---|---|---|
| `--bind` | text | Bind address: Bind the port to this address only, such as 127.0.0.1 when only a proxy on this machine should reach it. |
| `--listen` | text | Unix socket: Listen on a unix socket instead of a port. |
| `--shards` | int | Shards: Worker processes sharing the port: the way one runtime uses more than one core. |
| `--domain` | list | Names: The names it is reached by through the entrance; empty for its own name. |
| `--cpus` | text | CPUs: The CPUs its I/O may run on, as 0-3,6. |

**TLS**

| flag | value | what it does |
|---|---|---|
| `--tls` |  | TLS: Encrypt its transport: terminate TLS on its port, or dial over it. |
| `--cert` | path | Certificate: The PEM certificate (chain allowed) a listener presents. |
| `--key` | path | Key: The PEM key of the certificate. |
| `--ca` | path | CA: On a listener: require client certificates from this CA (mutual TLS). On a client or proxy: the CA its servers are checked against. |
| `--acme` | list | ACME names: Names to get a Let's Encrypt certificate for, renewed by itself. |
| `--acme-email` | text | ACME e-mail: The address the CA writes to about the certificate. |

**Limits**

| flag | value | what it does |
|---|---|---|
| `--max-connections` (--max-conn) | int | Max connections: The most clients at once. |
| `--rate-limit` | int | Rate limit: Messages a second per connection. |
| `--global-rate-limit` | int | Global rate limit: Messages a second over all connections. |
| `--congestion` | text | Congestion control: The kernel's congestion control for its connections, such as bbr, which keeps its rate up under packet loss. |
| `--idle-timeout` | duration | Idle timeout: Close a connection that has received nothing for this long; off unless given. |
| `--read-buffer` | size | Read buffer: How much data may pile up from one connection before it is refused; 1M unless given. |
| `--write-buffer` | size | Write buffer: How much unsent data may queue up for one connection before it is dropped; 8M unless given. |
| `--drain` |  | Drain on stop: Finish what is in flight before stopping. |

**Output**

| flag | value | what it does |
|---|---|---|
| `--log` | path | State log: A file it appends each state change to. |

**Cache**

| flag | value | what it does |
|---|---|---|
| `--mode` | one of readonly, readwrite, admin | Access: What its clients may do: read, read and write, or everything. |
| `--persistent` | path | Persist to: The file it is kept in across restarts. |
| `--persistent-interval` | duration | Journal every: How often accepted writes reach the journal. |
| `--maxmemory` | size | Max memory: The most memory its data may take. |
| `--eviction` | one of noeviction, allkeys-lru, allkeys-random | When full: Refuse writes, or evict keys. |
| `--resp` |  | Redis protocol only: Speak RESP to every client, without detecting it. |
| `--replicate` | text | Follow: The leader cache it follows, host:port. |
| `--public` |  | Public: Serve clients on other machines too. |
| `--cluster` |  | Cluster map: Publish a slot map so cluster clients go straight to each shard. |

## Benchmarks

A ratio (×) is how many times better socketley did: more per second, or less time, memory or CPU; above 1× socketley is ahead. The range in brackets is the lowest and highest ratio across the passes.

### Redis protocol, one command per round trip

Redis 8.0.5, Valkey 9.0.4, 11 passes, 2026-11-03, socketley c7d4c42b.

| case | socketley | Redis | Valkey | socketley vs Redis | socketley vs Valkey |
|---|---|---|---|---|---|
| SET | 232 K /s (1.00 cores) | 203 K /s (1.00 cores) | 208 K /s (1.00 cores) | 1.08× (0.89–2.03) | 1.11× (0.86–2.00) |
| GET | 235 K /s (1.00 cores) | 206 K /s (1.00 cores) | 149 K /s (1.00 cores) | 1.03× (0.92–1.55) | 1.59× (0.97–2.15) |
| LPUSH | 230 K /s (1.00 cores) | 220 K /s (1.00 cores) | 240 K /s (1.00 cores) | 1.11× (0.91–2.08) | 0.96× (0.85–2.06) |
| LPOP | 237 K /s (1.00 cores) | 234 K /s (1.00 cores) | 241 K /s (1.00 cores) | 1.03× (0.92–1.75) | 1.01× (0.94–1.57) |
| SADD | 237 K /s (1.00 cores) | 188 K /s (1.00 cores) | 180 K /s (1.00 cores) | 1.25× (0.87–2.02) | 1.35× (1.05–2.13) |
| HSET | 229 K /s (1.00 cores) | 203 K /s (1.00 cores) | 228 K /s (1.00 cores) | 1.10× (0.84–1.69) | 0.99× (0.92–2.07) |
| ZADD | 234 K /s (1.00 cores) | 174 K /s (1.00 cores) | 209 K /s (1.00 cores) | 1.39× (0.89–1.93) | 1.18× (0.90–2.27) |

How it was measured: 6 redis-benchmark processes × 50 connections; servers on one core, clients on 20 others. Each server on one pinned core, every row at a full core: the rate is one core divided by the cost of an operation. At depth 1 that cost is mostly the kernel's per-message price, which all three pay alike, so the differences are small and the ranges wide; this VM halts idle vCPUs and every wakeup of a client costs the server a VM exit, which moves a server that answers each command with its own write more than one that batches.
