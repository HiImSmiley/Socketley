# Sync flags

From the manual page socketley(1).

A **sync** runtime is one job that carries files between a directory and a storage. Because each job is its own runtime, a job that goes wrong has its own line in **socketley ls**, its own figures, its own lines in the log and its own alert.

```
socketley create sync photos --dir /srv/photos --storage ui/photos \
    --credentials /etc/socketley/sync.creds --mode out -s
```

A sync runtime listens on nothing and takes no **-p**. **--shards** is refused, because the shards would share no socket and several processes would write one index.

### `--dir path`

The directory whose files are carried. Required. The path must be absolute, and the directory must exist when the runtime starts.

### `--storage target[,target...]`

Where the files go. Required. Each target takes one of three forms, with the bucket last:

### `ui/photos`

A storage runtime of this daemon, reached on its port at 127.0.0.1. A name with no scheme and no port always names a runtime, even when it contains dots.

### `10.0.0.5:9000/photos`

A host and a port, over plain HTTP.

### `https://files.example/photos`

A URL, http or https, with nothing between the host and the bucket.

A storage runtime that serves TLS itself must be named by its URL, since its port does not speak plain HTTP. Naming it by its runtime name is refused, and the error gives the URL to use. A bucket name follows the S3 rules: 3 to 63 characters of **a-z**, **0-9**, **.** and **-**. More than one target is accepted only with **--mode out**. Carrying two targets into one directory could not tell which target a file came from when they differ.

### `--mode out|in|inout`

Which way files are carried, in the same three words a server and a client take. **out** sends the directory to the storage, **in** brings the storage to the directory, and **inout** does both. Default: **out**.

### `--credentials file`

The file the job signs its requests with. Required, since a sync signs every request it makes. The file holds **access_key** and **secret_key** as *key = value* lines, plus **session_token** and **region** when they are needed. **#** begins a comment. A file that other users may read is refused, at create and at every read: **chmod 600** it.

### `--prefix key`

The key that everything is written under, below the bucket. Default: the bucket's root.

### `--every duration`

How often the job walks the whole directory, and with **in** or **inout** also lists the storage. The duration is written as **30s**, **10m**, **1h** or **1d**. **never** walks the directory once, at start. Default: one hour. A job that brings the storage here lists it once a minute when **--every** is never.

Between walks, inotify reports which files changed. A file is carried once it is written and closed, moved in or touched. It is removed once it is deleted. A directory that appears or disappears, or more events than the kernel keeps, causes a walk. When inotify is not available or its watches run out (**fs.inotify.max_user_watches**), the log says so once, and the walks alone find changes.

### `--repositories file`

Makes the job pull the git repositories one user keeps in a storage runtime, instead of carrying a directory. See **Git repositories** under **STORAGE FLAGS**. The job is then that user's own, and takes no **--dir**, **--storage** or **--credentials**. The storage runtime makes such a job for each of its users and writes the file; it is not meant to be made by hand.

### `--exclude pattern[,pattern...]`

Shell patterns for files and directories that are not carried, separated by commas. Spaces around the patterns are ignored: **'*.tmp, *.md, node_modules'**. A pattern with no slash names a file or directory at any depth, like a *.gitignore* line. A pattern with a slash is matched against the whole path below **--dir**, and its * crosses slashes. Nothing that matches is carried, and a matching directory is not walked.

**What it remembers.** A sync keeps an index of what it last carried, in *state-dir*/sync/*name*.index, with mode 0600. Without the index, a file deleted here could not be told apart from a file never carried. With it, the deleted file is removed from the far side and the new file is sent. Every record carries a checksum, and the first record that fails its checksum ends the file. So a crash costs at most carrying again what the last moments carried. A file is never believed carried when it was not. The index belongs to one directory and one prefix. When either changes, the index is started again: everything is carried once more and nothing is removed. **socketley remove** deletes the index, and a rename carries it along.

**How it carries.** The job sends up to eight requests at a time per target, each on a connection kept between requests, and never two requests about one file. A file above 512 MiB goes as a multipart upload in parts of 64 MiB, since one request carries at most 5 GiB. If a file changes while its parts are being sent, the upload is given up, and the file is carried again once it is written. Without TLS, a file's bytes go from the disk to the socket by splice. A link to a file is carried as the file it names. The link is removed at the walk that finds it pointing at nothing, since no event reports that a link's target is gone. A link to a directory is not followed. A **--dir** that holds the directory of a storage runtime it names, or lies inside it, is refused, since every object carried would be carried again.

**What it takes away.** A file is removed from the storage only when it is provably gone here: deleted, or a link to nothing. Three kinds of file are left where they are: a file the walk could not read, a file below a directory the walk may not enter, and a file that an **--exclude** names since it was carried. If a directory is empty while the index says files were carried from it, nothing is removed, and **last_error** says why. A disk that is not mounted looks exactly like that, and a bucket emptied because of it cannot be filled again.

**Both ways.** With **in** or **inout**, the job lists the storage first, at start and then at every **--every**. It compares each object with the index and with the file here. With **inout**, the walk follows each listing. A file the storage has and this side does not is brought here. It is fetched in ranges of 8 MiB, written below *.socketley-sync* in **--dir**, and given its name once it is whole. A file the storage changed since is brought again. A file the storage removed is removed here, unless it changed here since. At the start, a file that both sides have with the same length is taken to be the same file.

A file that both sides changed is kept twice, on both sides. This side's version stays at its name and is carried out over the storage's. The storage's version is kept beside it as *name (conflict date time).ext*. With **inout**, every write and removal sent carries the etag this side last saw. So if the storage made a change meanwhile, it refuses the request, and the next listing keeps both versions, rather than the later write winning. With **in**, nothing is carried out: a file changed here is put back as the storage has it, and this side's version is kept beside it. A key with an empty, **.** or **..** segment is not brought. A folder that is a link out of **--dir** is not written through. A listing with nothing in it removes nothing here.

**What a failure means.** A file the storage refuses, and a target that does not answer, are counted. Each is logged once for as long as the reason stays the same. A walk thirty seconds later tries again, whatever **--every** says. A target that stops answering holds up only its own queue, not the others. The runtime keeps running. A sync that keeps failing for three readings in a row raises an alert, with **last_error** as its detail. The alert clears once something is carried again. A named runtime that is not a storage, or does not exist, is a failure of the same kind.

**Its figures** (**socketley stats**) are **mode**, **dir**, **indexed** (files the index holds), **carried**, **removed**, **bytes_carried**, **waiting** (what is queued), **failures**, **failing** (failures since the last thing carried), **watched** (directories inotify watches), **brought** (files brought from the storage), **removed_here** (files removed here because the storage removed them), **conflicts** (files both sides changed), **last_run_secs** and **last_error**.
