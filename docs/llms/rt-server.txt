# server runtime

TCP, UDP, WebSocket and HTTP on one port, answered by Lua or by a built-in path

A **server** listens on one port and talks to whoever connects. Without a script it relays messages between clients; with Lua it becomes an API, a chat room or a game loop.

```
socketley create server chat -p 9000 -s                    # every line reaches every other client
socketley create server echo -p 9001 --send-to sender -s   # answers whoever spoke
socketley create server site -p 8080 --http /srv/site --http-cache -s
socketley create server api -p 9002 --lua api.lua --cache store -s
```

> Warning: `--cache` also stores every ordinary message in the cache, under keys `1`, `2`, `3`… And `--http` injects a WebSocket script into every HTML page.

## What it does

- **One port, several protocols**: TCP, WebSocket, HTTP and RESP, [told apart by their first bytes](man-server-flags.txt); `--udp` for datagrams.
- **Static files**: `--http` serves a directory; `--http-cache` holds it in memory.
- **Lua handlers**: Per message, connection, HTTP request and WebSocket upgrade; see [Lua](lua.txt).
- **Relaying without code**: `--mode` and `--send-to` decide who hears a message.
- **Upstreams**: `-u host:port` dials other servers; the script hears them in `on_upstream`.
- **A cache beside it**: With `--cache name`, clients send `cache <command>`; see [cache access](man-server-flags.txt).
- **Several cores**: `--shards N` runs N processes on one port; see [sharding](man-server-flags.txt).

## Works with

A [proxy](rt-proxy.txt) in front for names and TLS, a [cache](rt-cache.txt) behind for state, a [client](rt-client.txt) to chain servers. Its counters reach [metrics](rt-metrics.txt) without setup.

## Flags

Every flag a server runtime takes, by group.

**Basics**

| flag | value | what it does |
|---|---|---|
| `-p` | int | Port: The port it listens on (a client: the port of its target). |
| `-s` |  | Start now: Start it as soon as it is made. |
| `-g` (--group) | text | Group: Puts it in a group; a proxy with --backend @group reaches every member. |
| `--lua` | path | Lua script: A script with the runtime's callbacks, run at start. |

**Network**

| flag | value | what it does |
|---|---|---|
| `--bind` | text | Bind address: Bind the port to this address only, such as 127.0.0.1 when only a proxy on this machine should reach it. |
| `--listen` | text | Unix socket: Listen on a unix socket instead of a port. |
| `--shards` | int | Shards: Worker processes sharing the port: the way one runtime uses more than one core. |
| `--domain` | list | Names: The names it is reached by through the entrance; empty for its own name. |
| `--cpus` | text | CPUs: The CPUs its I/O may run on, as 0-3,6. |

**TLS**

| flag | value | what it does |
|---|---|---|
| `--tls` |  | TLS: Encrypt its transport: terminate TLS on its port, or dial over it. |
| `--cert` | path | Certificate: The PEM certificate (chain allowed) a listener presents. |
| `--key` | path | Key: The PEM key of the certificate. |
| `--ca` | path | CA: On a listener: require client certificates from this CA (mutual TLS). On a client or proxy: the CA its servers are checked against. |
| `--acme` | list | ACME names: Names to get a Let's Encrypt certificate for, renewed by itself. |
| `--acme-email` | text | ACME e-mail: The address the CA writes to about the certificate. |

**Limits**

| flag | value | what it does |
|---|---|---|
| `--max-connections` (--max-conn) | int | Max connections: The most clients at once. |
| `--rate-limit` | int | Rate limit: Messages a second per connection. |
| `--global-rate-limit` | int | Global rate limit: Messages a second over all connections. |
| `--congestion` | text | Congestion control: The kernel's congestion control for its connections, such as bbr, which keeps its rate up under packet loss. |
| `--idle-timeout` | duration | Idle timeout: Close a connection that has received nothing for this long; off unless given. |
| `--read-buffer` | size | Read buffer: How much data may pile up from one connection before it is refused; 1M unless given. |
| `--write-buffer` | size | Write buffer: How much unsent data may queue up for one connection before it is dropped; 8M unless given. |
| `--drain` |  | Drain on stop: Finish what is in flight before stopping. |

**Output**

| flag | value | what it does |
|---|---|---|
| `--log` | path | State log: A file it appends each state change to. |
| `-w` | path | Message file: A file every received message is written to. |
| `-b` |  | Print messages: Print every received message. |
| `-bp` |  | …with name: Print them with the runtime's name before each. |
| `-bt` |  | …with time: Print them with the time before each. |
| `-bpt` (-btp) |  | …with time and name: Print them with the time and the name before each. |

**Server**

| flag | value | what it does |
|---|---|---|
| `--mode` | one of inout, in, out, master | Mode: Who talks: both ways, in only, out only, or one master broadcasting. |
| `--send-to` | list | Answer to: Who the built-in path answers: sender, others, master. |
| `--udp` |  | UDP: Datagrams instead of a stream. |
| `--http` | path | Static files: Serve this directory over HTTP. |
| `--http-cache` |  | Files in memory: Read the static files into memory at start. |
| `--compress` |  | Compressed copies: Serve a file's .br or .gz copy next to it to clients that accept it, unless the copy is older than the file. |
| `--no-inject` |  | Pages as they are: Serve each page exactly as the file holds it, without the WebSocket script. |
| `--master-pw` | text | Master password: The password that claims master mode. |
| `--no-master-pw` |  | No master password: Take the master password away, which ends master mode. |
| `--cache` | text | Cache: A cache runtime its scripts and clients use. |
| `--origins` | list | Web origins: Other web origins whose pages may open a WebSocket to it; * for any. |
| `-u` (--upstream) | list | Upstreams: Servers it relays to, host:port each. |

## Benchmarks

A ratio (×) is how many times better socketley did: more per second, or less time, memory or CPU; above 1× socketley is ahead. The range in brackets is the lowest and highest ratio across the passes.

### HTTP: static files and a fixed answer

nginx 1.28.3, 9 passes, 2026-11-03, socketley c7d4c42b.

| case | socketley | nginx | socketley vs nginx |
|---|---|---|---|
| 1 KiB file, keep-alive, 256 connections | 281 K req/s (1.00 cores) | 52 K req/s (1.00 cores) | 5.31× (4.95–5.82) |
| 64 KiB file, keep-alive, 256 connections | 93 K req/s (1.00 cores) | 45 K req/s (1.00 cores) | 2.08× (1.98–2.13) |
| 1 KiB file, a connection per request, 64 at once | 87 K req/s (1.00 cores) | 33 K req/s (1.00 cores) | 2.64× (2.56–2.86) |
| fixed answer (Lua handler / nginx return), keep-alive | 225 K req/s (1.00 cores) | 76 K req/s (1.00 cores) | 2.88× (2.82–3.08) |

Caveat: likely higher on this VM than on hardware; see the notes.

How it was measured: wrk 8 threads, 8 s a run; each server on one core, wrk on 20 others. socketley --http dir --http-cache against nginx with one worker, sendfile, open_file_cache and access logs off. Files are .txt: socketley adds a WebSocket script to every .html it serves, by design. The fixed answer is a Lua on_http_request on socketley and a return 200 on nginx, which runs no script at all. Read the 1 KiB keep-alive row with this machine in mind: nginx answers each request with its own write and wakeup, and on this VM waking a halted vCPU costs an exit, which costs a server that does that more than one that batches. A single unpublished pass on another VM (16 cores) read 1.85× for the same row.
