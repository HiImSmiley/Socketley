# tunnel runtime

Makes a machine without an address of its own reachable through an edge it dials

A **tunnel** makes a machine with no address of its own reachable, such as one at home behind a router. An **agent** there dials out to an **edge** the internet reaches; nothing is opened on the router.

```
# on the machine with the address
socketley create tunnel edge --mode edge -p 9450 --domain edge --idp auth -s
# on the machine at home, signed in as an admin of auth
socketley tunnel join https://edge.example.com --http home=127.0.0.1:8123 \
    --tcp mc:25565=127.0.0.1:25565
```

## What it does

- **HTTP services**: Named beside the edge, such as `home.example.com`.
- **TCP services**: A port on the edge, carried unchanged to the agent.
- **Joining**: `socketley tunnel join` as an idp admin, or a one-time `invite` used with `--join`.
- **ssh through 443**: `--forward` carries a signed-in person to the named addresses, via `tunnel connect` or `tunnel ssh`.
- **Share a port**: `socketley tunnel share` publishes a local port for a while, optionally public.

## Works with

The edge machine needs what the [public HTTPS recipe](deploy.txt) sets up: a [dns](rt-dns.txt) runtime, which answers the services' names, and its entrance [proxy](rt-proxy.txt), which terminates TLS. It also needs an [idp](rt-idp.txt) runtime, here `auth`: its admins may join agents, and its users sign in for `--forward`.

## Flags

Every flag a tunnel runtime takes, by group.

**Basics**

| flag | value | what it does |
|---|---|---|
| `-p` | int | Port: The port it listens on (a client: the port of its target). |
| `-s` |  | Start now: Start it as soon as it is made. |

**Network**

| flag | value | what it does |
|---|---|---|
| `--bind` | text | Bind address: Bind the port to this address only, such as 127.0.0.1 when only a proxy on this machine should reach it. |
| `--domain` | list | Names: The names it is reached by through the entrance; empty for its own name. |

**Output**

| flag | value | what it does |
|---|---|---|
| `--log` | path | State log: A file it appends each state change to. |

**Tunnel**

| flag | value | what it does |
|---|---|---|
| `--mode` | one of edge, agent | Mode: An edge agents dial out to, or an agent dialling one. |
| `--to` | text | Edge: The edge an agent dials, its https address. |
| `--join` | text | Invitation: What `socketley tunnel <edge> invite` printed, used once to join. |
| `--offer` | list | Offers: What an agent carries the edge's streams to: service=host:port each. |
| `--forward` | list | Forward: Where an edge forwards a signed-in user's stream, as ssh's ProxyCommand needs. |
| `--idp` | text | Identity provider: The idp runtime whose signed-in people may use --forward. |
| `--idp-audience` | list | Audiences: The clients whose access tokens --forward takes. |

## Benchmarks

A ratio (×) is how many times better socketley did: more per second, or less time, memory or CPU; above 1× socketley is ahead. The range in brackets is the lowest and highest ratio across the passes.

### A TCP service behind an edge

frp 0.71.1, 9 passes, 2026-11-03, socketley c7d4c42b.

| case | socketley | frp | socketley vs frp |
|---|---|---|---|
| round trip through the tunnel, 64 B echo | 88.5 µs (0.87 cores) | 168 µs (1.35 cores) | 1.90× (1.88–1.91) |
| throughput, 512 MiB echoed through the tunnel | 649.0 MiB/s (1.92 cores) | 855.0 MiB/s (1.84 cores) | 0.76× (0.72–0.82) |

How it was measured: tb_client, one connection; agent and edge (frpc and frps) on the same two cores, the echo service on a third. socketley agent and edge against frpc and frps, the service an echo server, one connection. socketley answers a round trip in about half frp's time and moves bulk data at three quarters of its rate.
