# mqtt runtime

MQTT 3.1, 3.1.1 and 5.0 broker on TCP, TLS and WebSocket, with sessions and rules

An **mqtt** runtime is an MQTT broker (3.1, 3.1.1 and 5.0) for devices, apps and browsers. A client that disconnects keeps its session and the messages it missed until it returns or the session expires.

```
socketley mqtt passwd /etc/socketley/mqtt.users sensor-17
socketley create mqtt broker --users /etc/socketley/mqtt.users \
    --acl /etc/socketley/mqtt.acl --ws 8083 --persistent on -s
mosquitto_sub -h 127.0.0.1 -u sensor-17 -P secret -t 'home/#'
```

## What it does

- **Full protocol**: QoS 0, 1 and 2, retained messages, wills, shared subscriptions and the 5.0 properties.
- **TCP, TLS, WebSocket**: Port 1883, or 8883 with `--tls`, and WebSocket on `--ws`.
- **Users**: A password file (`--users`), client certificates (`--ca`), [idp](rt-idp.txt) tokens, or `--anonymous`.
- **Topic rights**: Per user in `--acl`.
- **Survives restarts**: `--persistent` keeps sessions and retained messages.
- **Routes**: `--routes` hands matching messages to other runtimes.

## Works with

Routes deliver to a [cache](rt-cache.txt), [db](rt-db.txt), [storage](rt-storage.txt), [server](rt-server.txt) or another broker. A storage's events and `socketley.mqtt.publish` from any [script](lua.txt) reach its subscribers.

## Flags

Every flag a mqtt runtime takes, by group.

**Basics**

| flag | value | what it does |
|---|---|---|
| `-p` | int | Port: The port it listens on (a client: the port of its target). |
| `-s` |  | Start now: Start it as soon as it is made. |
| `-g` (--group) | text | Group: Puts it in a group; a proxy with --backend @group reaches every member. |
| `--lua` | path | Lua script: A script with the runtime's callbacks, run at start. |

**Network**

| flag | value | what it does |
|---|---|---|
| `--bind` | text | Bind address: Bind the port to this address only, such as 127.0.0.1 when only a proxy on this machine should reach it. |
| `--shards` | int | Shards: Worker processes sharing the port: the way one runtime uses more than one core. |
| `--cpus` | text | CPUs: The CPUs its I/O may run on, as 0-3,6. |

**TLS**

| flag | value | what it does |
|---|---|---|
| `--tls` |  | TLS: Encrypt its transport: terminate TLS on its port, or dial over it. |
| `--cert` | path | Certificate: The PEM certificate (chain allowed) a listener presents. |
| `--key` | path | Key: The PEM key of the certificate. |
| `--ca` | path | CA: On a listener: require client certificates from this CA (mutual TLS). On a client or proxy: the CA its servers are checked against. |

**Limits**

| flag | value | what it does |
|---|---|---|
| `--max-connections` (--max-conn) | int | Max connections: The most clients at once. |
| `--write-buffer` | size | Write buffer: How much unsent data may queue up for one connection before it is dropped; 8M unless given. |

**Output**

| flag | value | what it does |
|---|---|---|
| `--log` | path | State log: A file it appends each state change to. |

**MQTT**

| flag | value | what it does |
|---|---|---|
| `--users` | path | Users: Password accounts, one user:hash per line, as `socketley mqtt passwd` writes them. |
| `--idp` | text | Identity provider: The idp runtime whose access tokens sign clients in, given as the password. |
| `--idp-audience` | list | Token clients: The idp's clients whose access tokens it takes; a token of any other is refused. |
| `--acl` | path | Access rules: Who may publish and subscribe to what: user, topic and pattern lines, read again when it changes. |
| `--anonymous` |  | Anonymous: Let clients in without credentials, as the access rules allow. |
| `--routes` | path | Topic rules: Where messages go besides their subscribers: a cache, a db, a storage, a server or another broker. |
| `--ws` | int | WebSocket port: A port browsers reach the broker on over WebSocket. |
| `--persistent` | path | Persist to: The file sessions and retained messages are kept in across restarts; on puts it in the state directory. |
| `--persistent-interval` | duration | Write every: How often what changed reaches that file. |

**MQTT limits**

| flag | value | what it does |
|---|---|---|
| `--max-packet` | size | Max packet: The largest packet a client may send; 256K unless given. |
| `--session-expiry` | duration | Session expiry: The longest a session outlives its connection; 1d unless given. |
| `--session-queue` | int | Session queue: Messages kept for one session while its client is away; 1000 unless given. |
| `--retained-max` | size | Retained bytes: The most bytes retained messages take; 64M unless given. |
| `--max-sessions` | int | Max sessions: The most sessions it keeps, connected or not; 100000 unless given. |
| `--keepalive-max` | int | Max keep alive: The longest keep alive a client is granted, in seconds; 1200 unless given. |

## Benchmarks

A ratio (×) is how many times better socketley did: more per second, or less time, memory or CPU; above 1× socketley is ahead. The range in brackets is the lowest and highest ratio across the passes.

### MQTT broker, deliveries per second

Mosquitto 2.0.22, 9 passes, 2026-11-03, socketley c7d4c42b.

| case | socketley | Mosquitto | socketley vs Mosquitto |
|---|---|---|---|
| fan-in: 16 publishers to 1 subscriber, QoS 0, 64 B | 8.00 M msg/s (0.97 cores) | 793 K msg/s (0.99 cores) | 10.11× (9.96–10.28) |
| fan-out: 1 publisher to 100 subscribers, QoS 0, 64 B | 11.98 M msg/s (1.00 cores) | 502 K msg/s (0.99 cores) | 23.02× (20.48–30.99) |
| fan-out: 1 publisher to 50 subscribers, QoS 1, 64 B | 1.46 M msg/s (1.00 cores) | 69 K msg/s (1.00 cores) | 21.20× (21.02–21.42) |
| round trip, QoS 1 publish to own delivery | 26.6 µs (0.91 cores) | 42.7 µs (0.68 cores) | 1.61× (1.60–1.62) |

How it was measured: mqbench (MQTT 3.1.1), 6 s a run; each broker on one core, mqbench on 20 others. MQTT 3.1.1, 64-byte payloads; Mosquitto with persistence off and unbounded queues, socketley --anonymous --session-queue 100000. A fan-out delivery costs Mosquitto about 4 µs of CPU, one write each; socketley coalesces the writes to a subscriber, which is the whole of the fan-out difference. The round trip is a QoS 1 publish to the publisher's own subscription.
