# storage runtime

S3 object storage over a directory, with versioning, replication, a web drive and git

A **storage** runtime serves the S3 API over one directory, so boto3, the AWS CLI, rclone and other S3 clients keep objects on this machine's disk. It adds a web drive with share links and media.

```
socketley create storage files -p 9000 --dir /srv/objects \
    --credentials /etc/socketley/storage.creds -s
aws --endpoint-url http://127.0.0.1:9000 s3 mb s3://photos
aws --endpoint-url http://127.0.0.1:9000 s3 cp beach.jpg s3://photos/
```

## What it does

- **The S3 API**: SigV4, multipart uploads, [S3 Select](man-storage-flags.txt); see [operations](man-storage-flags.txt).
- **Users and policies**: [Users](man-storage-flags.txt), [IAM](man-storage-flags.txt), [bucket policies](man-storage-flags.txt), [STS](man-storage-flags.txt).
- **Keeping versions**: [Versioning](man-storage-flags.txt), [object lock](man-storage-flags.txt), [lifecycle](man-storage-flags.txt), [tiers](man-storage-flags.txt).
- **Copies**: [Replication](man-storage-flags.txt) to other S3 endpoints, or a [cluster](man-storage-flags.txt) of nodes.
- **On disk**: [Compression](man-storage-flags.txt), [encryption](man-storage-flags.txt), and `--fsync` for [durability](man-storage-flags.txt).
- **Around the data**: [Webhooks](man-storage-flags.txt), [bucket websites](man-storage-flags.txt), [quotas](man-storage-flags.txt).
- **Web interface**: A [drive](man-storage-flags.txt), [git repositories](man-storage-flags.txt), sign-in through an [idp](rt-idp.txt).

## Works with

[sync](rt-sync.txt) carries directories into it, [mail](rt-mail.txt) keeps mailboxes in it, [metrics](rt-metrics.txt) archives to it.

## Flags

Every flag a storage runtime takes, by group.

**Basics**

| flag | value | what it does |
|---|---|---|
| `-p` | int | Port: The port it listens on (a client: the port of its target). |
| `-s` |  | Start now: Start it as soon as it is made. |
| `-g` (--group) | text | Group: Puts it in a group; a proxy with --backend @group reaches every member. |
| `--lua` | path | Lua script: A script with the runtime's callbacks, run at start. |

**Network**

| flag | value | what it does |
|---|---|---|
| `--bind` | text | Bind address: Bind the port to this address only, such as 127.0.0.1 when only a proxy on this machine should reach it. |
| `--listen` | text | Unix socket: Listen on a unix socket instead of a port. |
| `--shards` | int | Shards: Worker processes sharing the port: the way one runtime uses more than one core. |
| `--domain` | list | Names: The names it is reached by through the entrance; empty for its own name. |
| `--cpus` | text | CPUs: The CPUs its I/O may run on, as 0-3,6. |

**TLS**

| flag | value | what it does |
|---|---|---|
| `--tls` |  | TLS: Encrypt its transport: terminate TLS on its port, or dial over it. |
| `--cert` | path | Certificate: The PEM certificate (chain allowed) a listener presents. |
| `--key` | path | Key: The PEM key of the certificate. |
| `--ca` | path | CA: On a listener: require client certificates from this CA (mutual TLS). On a client or proxy: the CA its servers are checked against. |
| `--acme` | list | ACME names: Names to get a Let's Encrypt certificate for, renewed by itself. |
| `--acme-email` | text | ACME e-mail: The address the CA writes to about the certificate. |

**Limits**

| flag | value | what it does |
|---|---|---|
| `--max-connections` (--max-conn) | int | Max connections: The most clients at once. |
| `--congestion` | text | Congestion control: The kernel's congestion control for its connections, such as bbr, which keeps its rate up under packet loss. |
| `--idle-timeout` | duration | Idle timeout: Close a connection that has received nothing for this long; off unless given. |
| `--read-buffer` | size | Read buffer: How much data may pile up from one connection before it is refused; 1M unless given. |
| `--write-buffer` | size | Write buffer: How much unsent data may queue up for one connection before it is dropped; 8M unless given. |
| `--drain` |  | Drain on stop: Finish what is in flight before stopping. |

**Output**

| flag | value | what it does |
|---|---|---|
| `--log` | path | State log: A file it appends each state change to. |

**Storage**

| flag | value | what it does |
|---|---|---|
| `--dir` | path | Directory: Where the buckets live. Required. |
| `--credentials` | path | Credentials: A file of access:secret pairs and [users], read again when it changes. |
| `--access-key` | text | Access key: One access key, when there is no credentials file. |
| `--secret-key` | text | Secret key: Its secret. |
| `--anonymous` |  | Anonymous: Let in requests without credentials, as policies allow. |
| `--website-domain` | list | Website names: Names buckets' websites are reached under. |
| `--tls-offloaded` | list | TLS proxies: Proxies that end TLS in front of it, whose X-Forwarded-For names the client. |
| `--max-bytes` | size | Quota: The most bytes it holds. |

**Durability**

| flag | value | what it does |
|---|---|---|
| `--fsync` | one of always, interval, never | Sync to disk: When an answered write is on the disk. |
| `--fsync-interval` | duration | Sync every: How often --fsync interval syncs to disk. |
| `--scrub` | duration | Scrub every: Read every object back once in this long and check it; never unless given. |
| `--compress` | duration | Compress after: Compress a version once it has not been written for this long; off unless given. |
| `--mpu-expire` | duration | Abort uploads after: Abort a multipart upload open this long; never unless given. |

**Storage extras**

| flag | value | what it does |
|---|---|---|
| `--sse-key-file` | path | Encryption key: The 32-byte master key of server-side encryption. |
| `--sync` | one of never, active, per-user | Sync runtimes: Runtimes that pull users' git repositories: none, one for all, or one each. |
| `--acls` |  | ACLs: Accept ACLs on buckets that have no ownership controls; otherwise the bucket owner owns everything. |
| `--notify-targets` | path | Webhooks: The webhooks event notifications may go to. |
| `--replication-targets` | path | Replication targets: The S3 endpoints buckets may replicate to. |
| `--tiers` | path | Tiers: The S3 endpoints lifecycle may move versions to. |
| `--federation` | path | Federation: The OIDC provider and LDAP directory STS trusts. |
| `--nodes` | path | Cluster nodes: Make it a node of a storage cluster. |

**Storage**

| flag | value | what it does |
|---|---|---|
| `--idp` | text | Identity provider: The idp runtime the web interface signs in with; its users are the users of the same name here. |

## Benchmarks

A ratio (×) is how many times better socketley did: more per second, or less time, memory or CPU; above 1× socketley is ahead. The range in brackets is the lowest and highest ratio across the passes.

### S3 over HTTP, SigV4

MinIO 2025-09-07, 3 passes, 2026-11-10, socketley 0174a7a1.

| case | socketley | MinIO | socketley vs MinIO |
|---|---|---|---|
| GET 4 KiB, 1 connection | 21 K obj/s (0.63 cores) | 3.9 K obj/s (1.28 cores) | 5.29× (5.22–5.31) |
| GET 4 KiB, 64 connections | 451 K obj/s (3.78 cores) | 25 K obj/s (3.99 cores) | 18.17× (17.98–18.73) |
| GET 4 KiB, 128 connections | 557 K obj/s (3.92 cores) | 24 K obj/s (3.99 cores) | 23.11× (22.69–23.75) |
| GET 4 KiB, 64 connections, from 50,000 objects | 251 K obj/s (3.96 cores) | 24 K obj/s (3.99 cores) | 10.42× (10.10–10.51) |
| GET 1 MiB, 64 connections | 42 K obj/s (3.95 cores) | 6.0 K obj/s (3.96 cores) | 7.05× (6.97–7.12) |
| PUT 4 KiB, 64 connections, into an empty store | 79 K obj/s (3.75 cores) | 15 K obj/s (3.98 cores) | 5.11× (4.92–5.31) |

How it was measured: s3gen (Go, one process, a request in flight per connection), 4s a run, SigV4 over plain HTTP, PUT bodies aws-chunked and signed; both servers on the same four cores (socketley as four shards), s3gen on 20 others. MinIO single node, single drive; both on tmpfs, so the comparison is the servers' work and not a disk. MinIO is a Go server that limits itself on one core, hence four for both. s3gen signs every request with SigV4 as warp does (PUTs as signed aws-chunked bodies) and checks every answer's status, length and ETag; from 64 connections both servers fill their four cores. The 4 KiB rows read 2,500 objects, which socketley keeps as in-memory copies; the 50,000-object row reads past them, where every GET opens its file as MinIO's always do. The PUT row starts both servers afresh on empty storage for every pass, because MinIO reclaims deleted objects in the background and its puts slow while it does.
