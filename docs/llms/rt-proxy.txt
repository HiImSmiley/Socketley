# proxy runtime

HTTP and TCP reverse proxy: routes by name and path, health checks, retries, mTLS, FastCGI

A **proxy** forwards HTTP or plain TCP to backends, balances them and steers around failing ones. Without `--backend` it is the **entrance**, routing each request by name to the runtime that has it.

```
socketley create proxy gw -p 8080 --backend 127.0.0.1:9000 -s          # /gw/... goes to the backend
socketley create proxy web -p 8081 --backend @web --strategy round-robin \
    --health-check http --health-path /health -s
socketley create proxy db-tcp -p 5433 --protocol tcp --backend 10.0.0.7:5432 -s
socketley create proxy php -p 8082 --backend fastcgi://127.0.0.1:9000 --root /var/www/site -s
```

> By default a backend has 2 seconds to start answering, or the request gets a 504. Raise `--backend-timeout` for slow applications.

## What it does

- **Routing**: A request for `/gw/x` on proxy `gw` reaches the backend as `/x`; any other path, `/` included, gets 404. Through the entrance, a request for a `--domain` name passes unchanged.
- **Any backend**: `host:port`, `https://`, `unix:`, a runtime, an `@group`, `fastcgi://`.
- **Resilience**: [Health checks](man-proxy-flags.txt), a [circuit breaker](man-proxy-flags.txt), [retries](man-proxy-flags.txt); `--sidecar` turns all on.
- **Sign-in first**: `--auth bearer:`, `basic:` or `idp:` before anything reaches a backend.
- **TLS on both legs**: Its own listener, [client certificates](man-proxy-flags.txt), verified `https://` backends.
- **Lua filters**: `on_route` picks backends; a [filter chain](man-lua-configuration.txt) rewrites traffic.
- **Modern HTTP**: The entrance speaks HTTP/2 and HTTP/3; every proxy relays WebSocket.

## Works with

A [dns](rt-dns.txt) runtime makes the entrance and its certificates. `--auth idp:` signs people in through an [idp](rt-idp.txt).

## Flags

Every flag a proxy runtime takes, by group.

**Basics**

| flag | value | what it does |
|---|---|---|
| `-p` | int | Port: The port it listens on (a client: the port of its target). |
| `-s` |  | Start now: Start it as soon as it is made. |
| `-g` (--group) | text | Group: Puts it in a group; a proxy with --backend @group reaches every member. |
| `--lua` | path | Lua script: A script with the runtime's callbacks, run at start. |
| `--lua-ffi` |  | Lua FFI: Let the script require("ffi"): LuaJIT's calls into C and raw memory, where a wrong pointer ends the runtime's process. |

**Network**

| flag | value | what it does |
|---|---|---|
| `--bind` | text | Bind address: Bind the port to this address only, such as 127.0.0.1 when only a proxy on this machine should reach it. |
| `--listen` | text | Unix socket: Listen on a unix socket instead of a port. |
| `--shards` | int | Shards: Worker processes sharing the port: the way one runtime uses more than one core. |
| `--domain` | list | Names: The names it is reached by through the entrance; empty for its own name. |
| `--cpus` | text | CPUs: The CPUs its I/O may run on, as 0-3,6. |

**TLS**

| flag | value | what it does |
|---|---|---|
| `--tls` |  | TLS: Encrypt its transport: terminate TLS on its port, or dial over it. |
| `--cert` | path | Certificate: The PEM certificate (chain allowed) a listener presents. |
| `--key` | path | Key: The PEM key of the certificate. |
| `--ca` | path | CA: On a listener: require client certificates from this CA (mutual TLS). On a client or proxy: the CA its servers are checked against. |
| `--acme` | list | ACME names: Names to get a Let's Encrypt certificate for, renewed by itself. |
| `--acme-email` | text | ACME e-mail: The address the CA writes to about the certificate. |

**Limits**

| flag | value | what it does |
|---|---|---|
| `--max-connections` (--max-conn) | int | Max connections: The most clients at once. |
| `--rate-limit` | int | Rate limit: Messages a second per connection. |
| `--global-rate-limit` | int | Global rate limit: Messages a second over all connections. |
| `--congestion` | text | Congestion control: The kernel's congestion control for its connections, such as bbr, which keeps its rate up under packet loss. |
| `--idle-timeout` | duration | Idle timeout: Close a connection that has received nothing for this long; off unless given. |
| `--read-buffer` | size | Read buffer: How much data may pile up from one connection before it is refused; 1M unless given. |
| `--write-buffer` | size | Write buffer: How much unsent data may queue up for one connection before it is dropped; 8M unless given. |
| `--drain` |  | Drain on stop: Finish what is in flight before stopping. |

**Output**

| flag | value | what it does |
|---|---|---|
| `--log` | path | State log: A file it appends each state change to. |

**Server**

| flag | value | what it does |
|---|---|---|
| `--compress` |  | Compressed copies: Serve a file's .br or .gz copy next to it to clients that accept it, unless the copy is older than the file. |

**Proxy**

| flag | value | what it does |
|---|---|---|
| `--backend` | list | Backends: Where requests go: host:port, https://host, unix:/path, a runtime or @group. None makes it the entrance. |
| `--protocol` | one of http, tcp | Protocol: HTTP routes by path and name; TCP forwards bytes. |
| `--strategy` | one of round-robin, random, lua | Strategy: How a backend is picked. |
| `--auth` | text | Auth: Who may pass: bearer:<file of tokens> or basic:<credentials file>. |
| `--redirect-https` | text | Redirect to HTTPS: Answer every request with a redirect to HTTPS on this port (443 when empty). |
| `--backend-timeout` | duration | Backend timeout: How long a backend may take to begin its answer, 2s unless given; 0 waits for ever. |
| `--retry` | int | Retries: Try a failed request this many times on the next backend. |
| `--retry-all` |  | Retry POST too: Also retry requests that are not idempotent. |

**Health**

| flag | value | what it does |
|---|---|---|
| `--health-check` | one of tcp, http | Health check: Check the backends by connecting, or by asking a path. |
| `--health-interval` | duration | Every: Time between two checks. |
| `--health-path` | text | Path: The path an HTTP check asks. |
| `--health-threshold` | int | Failures: Failed checks before a backend is out. |
| `--circuit-threshold` | int | Circuit after: Errors in a row that take a backend out. |
| `--circuit-timeout` | duration | Circuit open for: How long a backend stays out before it is tried again. |
| `--sidecar` |  | Sidecar: Health checks, circuit breaker, retries and drain in one. |

**FastCGI**

| flag | value | what it does |
|---|---|---|
| `--root` | path | Document root: The directory of a fastcgi:// backend's scripts: a .php file under it is run, a path with no file goes to the index script. |
| `--fastcgi-root` | path | Server's root: The same directory as the application server sees it, when that is another path (a container). |
| `--index` | text | Index script: The script that directories and paths with no file go to; index.php unless given. |

**Proxy TLS**

| flag | value | what it does |
|---|---|---|
| `--client-ca` | path | Client CA: Clients must present a certificate signed by this CA. |
| `--client-cert` | path | Backend certificate: The certificate it presents to TLS backends. |
| `--client-key` | path | Backend key: That certificate's key. |

## Benchmarks

A ratio (×) is how many times better socketley did: more per second, or less time, memory or CPU; above 1× socketley is ahead. The range in brackets is the lowest and highest ratio across the passes.

### Reverse proxy, HTTP and TCP

HAProxy 3.2.25, nginx 1.28.3, 3 passes, 2026-11-10, socketley 0174a7a1.

| case | socketley | HAProxy | nginx | socketley vs HAProxy | socketley vs nginx |
|---|---|---|---|---|---|
| HTTP, 1 KiB, keep-alive, 32 connections | 52 K req/s (1.00 cores) | 41 K req/s (1.00 cores) | 29 K req/s (1.00 cores) | 1.26× (1.24–1.28) | 1.75× (1.74–1.76) |
| HTTP, 1 KiB, keep-alive, 256 connections | 71 K req/s (1.00 cores) | 36 K req/s (1.00 cores) | 31 K req/s (0.99 cores) | 2.01× (1.85–2.04) | 2.30× (2.19–2.34) |
| HTTP, 64 KiB, keep-alive, 256 connections | 30 K req/s (0.99 cores) | 22 K req/s (1.00 cores) | 16 K req/s (1.00 cores) | 1.37× (1.34–1.39) | 1.89× (1.86–1.91) |
| HTTP, 1 KiB, a connection per request, 64 at once | 44 K req/s (1.00 cores) | 28 K req/s (1.00 cores) | 21 K req/s (1.00 cores) | 1.57× (1.57–1.65) | 2.06× (2.04–2.10) |
| TCP relay, 1 KiB over HTTP keep-alive, 256 connections | 95 K req/s (1.00 cores) | 43 K req/s (1.00 cores) | 65 K req/s (1.00 cores) | 2.15× (2.15–2.33) | 1.43× (1.36–1.53) |

How it was measured: wrk 8 threads, 4 s a run; each proxy on one core, the nginx backend on four, wrk on 20. All three forward /px/… with the prefix stripped to one nginx backend with four workers, each proxy saturating its core. HAProxy runs one thread with http-reuse always; nginx keeps 256 idle backend connections (keepalive 256); socketley keeps as many backend connections as were busy at once. The kernel keeps at most 2,048 connections in TIME-WAIT for every arm (net.ipv4.tcp_max_tw_buckets, 131,072 by default), so a pass with a connection per request does not wait out the closed connections of the one before.

### Reverse proxy on four cores

HAProxy 3.2.25, nginx 1.28.3, 3 passes, 2026-11-10, socketley 0174a7a1.

| case | socketley | HAProxy | nginx | socketley vs HAProxy | socketley vs nginx |
|---|---|---|---|---|---|
| HTTP, 1 KiB, keep-alive, 32 connections | 151 K req/s (3.99 cores) | 109 K req/s (4.00 cores) | 102 K req/s (3.73 cores) | 1.36× (1.35–1.39) | 1.48× (1.41–1.50) |
| HTTP, 1 KiB, keep-alive, 256 connections | 166 K req/s (3.99 cores) | 128 K req/s (4.00 cores) | 116 K req/s (4.00 cores) | 1.30× (1.29–1.32) | 1.43× (1.41–1.45) |
| HTTP, 64 KiB, keep-alive, 256 connections | 93 K req/s (3.99 cores) | 75 K req/s (3.99 cores) | 56 K req/s (3.99 cores) | 1.24× (1.22–1.25) | 1.68× (1.65–1.68) |
| HTTP, 1 KiB, a connection per request, 64 at once | 105 K req/s (3.96 cores) | 82 K req/s (3.98 cores) | 74 K req/s (3.83 cores) | 1.28× (1.25–1.29) | 1.42× (1.42–1.42) |
| TCP relay, 1 KiB over HTTP keep-alive, 256 connections | 206 K req/s (3.99 cores) | 171 K req/s (4.00 cores) | 180 K req/s (4.00 cores) | 1.20× (1.18–1.20) | 1.14× (1.13–1.15) |

How it was measured: wrk 16 threads, 4 s a run; socketley as four shards, HAProxy with four threads and nginx with four workers, each pinned to one of the same four cores; the nginx backend (eight workers) on eight others, wrk (16 threads) on 14. The same rows as the one-core set, the same wrk for every arm; the backend is not what the proxies run into. As in the server set, each wrk thread holds connections on all four of socketley's shards, so part of every arm's CPU is waking the co-located client across cores. The kernel keeps at most 2,048 connections in TIME-WAIT for every arm (net.ipv4.tcp_max_tw_buckets, 131,072 by default), so a pass with a connection per request does not wait out the closed connections of the one before.
