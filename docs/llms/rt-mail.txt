# mail runtime

Mail server: SMTP, submission, IMAP, POP3, JMAP and webmail, mailboxes in a storage

A **mail** runtime is a mail server: it receives mail for your domains, sends your users' mail, and keeps their mailboxes. Other runtimes, the CLI and the daemon's alerts can send through it.

```
socketley create mail m -p 25 --dns ns --no-reply -s            # only sends: alerts, notices
socketley send m --to ops@example.com --subject "Backup done" --text ok

socketley create mail m -p 25 --dns ns --idp auth --storage files/mail \
    --submission 587 --imap 143 --tls -s
```

## What it does

- **Receiving**: SMTP with SPF, DKIM, DMARC and ARC checks, optional greylisting and blocklists, and Sieve filters per user.
- **Safe spool**: A message is synced to disk before the sender is told 250.
- **Sending**: `--submission` and `--submissions` ports, DKIM signing, DANE and MTA-STS, or a `--relay` smarthost.
- **Reading**: IMAP, POP3, JMAP, and webmail on `--web`.
- **DNS records**: Publishes MX, SPF, DKIM, DMARC, MTA-STS and more through `--dns`.
- **Operating it**: `socketley mail m queue`, `show`, `flush`, `trace`; `on_rcpt` and `on_message` in [Lua](lua.txt).

## Works with

- [dns](rt-dns.txt) publishes its domains' records.
- [idp](rt-idp.txt) provides its users.
- [storage](rt-storage.txt) holds the mailboxes.

## Flags

Every flag a mail runtime takes, by group.

**Basics**

| flag | value | what it does |
|---|---|---|
| `-p` | int | Port: The port it listens on (a client: the port of its target). |
| `-s` |  | Start now: Start it as soon as it is made. |
| `-g` (--group) | text | Group: Puts it in a group; a proxy with --backend @group reaches every member. |
| `--lua` | path | Lua script: A script with the runtime's callbacks, run at start. |

**Network**

| flag | value | what it does |
|---|---|---|
| `--bind` | text | Bind address: Bind the port to this address only, such as 127.0.0.1 when only a proxy on this machine should reach it. |
| `--shards` | int | Shards: Worker processes sharing the port: the way one runtime uses more than one core. |
| `--domain` | list | Names: The names it is reached by through the entrance; empty for its own name. |
| `--cpus` | text | CPUs: The CPUs its I/O may run on, as 0-3,6. |

**TLS**

| flag | value | what it does |
|---|---|---|
| `--tls` |  | TLS: Encrypt its transport: terminate TLS on its port, or dial over it. |
| `--cert` | path | Certificate: The PEM certificate (chain allowed) a listener presents. |
| `--key` | path | Key: The PEM key of the certificate. |

**Limits**

| flag | value | what it does |
|---|---|---|
| `--max-connections` (--max-conn) | int | Max connections: The most clients at once. |

**Output**

| flag | value | what it does |
|---|---|---|
| `--log` | path | State log: A file it appends each state change to. |

**Mail**

| flag | value | what it does |
|---|---|---|
| `--mail-domain` | list | Mail domains: The domains whose mail it takes; the zones of --dns where none is given. |
| `--dns` | text | DNS runtime: The dns runtime whose zones are its domains, given their MX, SPF, DKIM and DMARC records. |
| `--hostname` | text | Host name: The name it greets with and its MX records name; mail.<first domain> unless given. |
| `--no-reply` |  | No-reply sender: Send as no-reply@<domain> where no sender is said, and take no mail to that address. |
| `--idp` | text | Identity provider: The idp runtime whose users have mailboxes here and sign in to send. |

| `--storage` | text | Mailboxes: The storage runtime, and bucket, the mailboxes are kept in. |
| `--users` | path | Users: Accounts that sign in to send, one user:hash per line, as `socketley mqtt passwd` writes them. |
| `--aliases` | path | Aliases: Addresses it accepts besides the users', one `address target` per line. |
| `--relay` | text | Smarthost: Send all mail for elsewhere through this server, smtp[s]://[user:password@]host[:port]. |

**Mail ports**

## Benchmarks

A ratio (×) is how many times better socketley did: more per second, or less time, memory or CPU; above 1× socketley is ahead. The range in brackets is the lowest and highest ratio across the passes.

### Mail: delivery in, IMAP and POP3 out

Postfix 3.10.6 + Dovecot 2.4.2, 7 passes, 2026-11-07, socketley 608e28c6.

| case | socketley | Postfix 3.10.6 + Dovecot | socketley vs Postfix 3.10.6 + Dovecot |
|---|---|---|---|
| SMTP in, 4 KiB messages, 64 connections, 10 a connection | 408.0 msg/s (0.11 cores) | 109.0 msg/s (0.26 cores) | 3.72× (3.21–4.00) |
| SMTP in, 64 KiB messages, 64 connections, 10 a connection | 209.0 msg/s (0.16 cores) | 56.3 msg/s (0.16 cores) | 3.93× (3.21–4.18) |
| IMAP: LOGIN and LOGOUT, 8 clients | 126.0 sign-ins/s (0.99 cores) | 64.4 sign-ins/s (0.99 cores) | 1.96× (1.95–1.97) |
| IMAP: LOGIN, SELECT, FETCH every header of 10,000, 8 clients | 487 K msg/s (0.99 cores) | 125 K msg/s (0.99 cores) | 3.88× (3.85–3.92) |
| IMAP: LOGIN, SELECT, FETCH 1,000 whole 64 KiB messages, 8 clients | 18 K msg/s (0.99 cores) | 13 K msg/s (0.99 cores) | 1.38× (1.35–1.49) |
| POP3: USER, PASS, RETR 1,000 64 KiB messages one by one, 8 clients | 12 K msg/s (0.99 cores) | 7.0 K msg/s (1.00 cores) | 1.77× (1.67–1.80) |

How it was measured: smtp-source (64 processes x 1 connections); mailload.py (8 asyncio processes x 1 connection), 8 s a run; every process of each on the same one core (socketley's daemon, idp, storage and mail; Postfix and Dovecot); smtp-source and mailload on 20 others; data on the VM's ext4 disk. Postfix hands each message over LMTP to Dovecot's Maildir and index; socketley's mail runtime writes it into its storage runtime. Both sync to disk (about 4 ms a sync here) before a message counts, so the SMTP rows are bound by syncs, not cores, and are timed until the last message is in its mailbox. Every sign-in hashes the password: scrypt in socketley, yescrypt in Dovecot. Dovecot 2.4's lmtp_user_concurrency_limit is set to unlimited, 2.3's default, since 10 made Postfix wait out five-minute retries.
